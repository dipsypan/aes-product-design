## 输入与返回契约

- 处理下一代端点安全中的匹配规则管理，包括以文件 Hash、IP、域名、文件路径等单个主体值作为匹配依据的规则，以及由多个行为、指标或属性条件组合而成的规则。
- 负责明确列表页、新增弹窗、编辑弹窗、批量操作、筛选、匹配内容、校验、冲突和生命周期。
- 通用字段统一使用“匹配规则内容”：单主体模式下表示主体对象值，条件组合模式下表示完整条件表达式。
- 默认使用本文件规定的页面骨架和模式分支。不得把参考页面中的条件字段、操作符或处置字段写死为所有规则必备字段。
- 不处理依赖优先级、继承、分配对象和排除对象合成最终配置的策略；此类需求必须使用策略业务模型。
- 未覆盖的通用表单与列表规则继续读取 `../templates/form.md`、`../templates/list.md`；本文件只定义规则业务结构、模式差异和提交语义。
- 出现生效资产列或列表顶部提示条时，展示、位置、交互和验收统一执行 `../templates/list.md`，本文件不重复定义视觉规则。

## 核心判断

生成方案前必须确定：

1. `match_mode`：单主体匹配 `subject`，还是条件组合匹配 `condition-combination`。
2. `rule_effect`：命中后放通 `allow`、拦截 `block`、检测/告警 `detect`，还是需求定义的其他结果 `custom`。
3. `subject_type_mode`：仅单主体模式判断，主体类型固定还是可选择。
4. `asset_scope`：固定全局生效，还是允许配置生效资产。
5. `expiry_mode`：永久、永久/自定义可选，还是固定有效期。

`match_mode` 和 `rule_effect` 是业务建模结果，不默认作为表单选项；只有同一入口确实支持用户切换时才显示对应控件。
核心判断所需事实未由需求、真实页面或接口明确时标记为待确认，不得自行把生效范围或有效期补成“全局、永久”等业务默认值。

业务不变量：

- 列表一行表示一条完整规则实例，编辑始终只处理一条规则。
- 单主体模式下一行对象值生成一条独立规则，可批量新增。
- 条件组合模式下整个条件表达式生成一条规则，条件和条件组不得拆成多条列表记录。
- 列表初始为空且没有内置规则；不得引入策略类的优先级、复制、继承或分配冲突模型。

## 参考基准

按能力参照，不整页照搬：

| 能力 | 参考页面 | 仅继承 |
| --- | --- | --- |
| 规则列表 | 自定义 IOC、白名单管理列表 | 页面骨架、工具栏、批量操作、行内编辑 |
| 单主体匹配 | 自定义 IOC、白名单新增/编辑弹窗 | 主体值输入、启用状态、备注及弹窗承载 |
| 条件组合匹配 | 真实条件组合规则页或用户提供的参考图 | 条件字段、操作符、值、逻辑关系、“新增条件”和“新增条件组” |
| 生效资产 | 任务中心 -> 新增快速扫描任务 -> 任务对象 | `scopeType/includeAssets/excludeAssets` 及资产选择联动 |
| 资产适用检测 | 安全策略列表 -> 资产适用策略检测 | 资产检索、适用结果及实际生效项标识 |
| 通用视觉与检索 | `prd-design-code`、`../templates/form.md`、`../templates/list.md` | 组件、布局、间距、表单状态和 `quick-filter-search` |

- 业务字段只由需求和“核心判断”决定；不得从 IOC 继承加黑、告警、过期时间，也不得从白名单继承特定主体类型或放通范围。
- 条件组合模式只继承构建器结构，不继承参考图中的“告警规则、日志规则、目的 IP、域名/URL”等具体条件。
- 优先级：用户明确需求 > 本模型业务契约 > 参考页面 > 通用设计 Reference。参考不可访问或与现状不一致时返回 `reference_gaps`，不得声称已对齐。

## 默认页面架构

默认页面清单：

```yaml
page_inventory:
  list_page: 规则列表页
  create_modal: 新增规则弹窗
  edit_modal: 编辑规则弹窗
  delete_confirm: 删除确认弹窗
  status_confirm: 启用/禁用确认弹窗
  import_modal: 条件性的批量导入弹窗
  result_modal: 条件性的批量结果弹窗
```

默认使用一张列表。单主体模式在同一入口管理多种主体时，通过“主体类型”字段和筛选区分；只有不同类型的字段、权限或生命周期明显不同时才拆成标签页。条件组合模式默认使用同一套条件字段目录，不按条件字段拆页。

## 列表页

### 列表能力声明

规则列表固定向 `../templates/list.md` 返回：

```yaml
list_type: basic-list
business_type: config-manage
search_mode: quick-filter-search
```

页面结构、表格头部布局、快速筛选与检索框交互、刷新、分页、列设置和通用状态全部执行 `../templates/list.md`，本文件不重复定义。

补充规则：
标题使用具体业务名称；
需在列表上方外显命中结果或影响范围或限制增加的规则上限，具体文案需要用户输入提供，位置和展示形式参考对象白名单的提示条形式；
列表不得使用策略卡片。空状态不生成示例或兜底规则，并保留“新增”。

### 工具栏与批量操作

固定顺序为 `新增`、`删除`、`启用`、`禁用`，依赖选中项的按钮无选中时禁用；`asset_scope=configurable` 时随后增加始终可点击的「资产适用规则检测」，固定全局生效时不显示。

- 单主体模式默认支持 `导入`；条件组合模式只有需求提供明确导入模板和表达式映射时才支持。
- 仅有审计、迁移诉求或参考模块已有能力时追加 `导出`。
- 删除、启用、禁用均需确认目标和数量，其余状态与反馈执行 `../templates/list.md`。
- 资产适用规则检测返回 `asset_applicability_check: { enabled: true, entity_type: rule, label: 资产适用规则检测 }`，点击完整复用安全策略检测流程，仅替换规则结果字段和接口映射。

### 规则业务检索字段

本模型固定返回 `search_mode: quick-filter-search`。控件位置、条件回显、组合查询、清空、重置、刷新和分页联动全部执行 `../templates/list.md`。

- `quick_filter_fields` 基线：启用状态、创建者、创建时间、最近修改时间。
- 条件追加：单主体模式的主体类型，以及按能力出现的生效资产、有效期、命中结果、处置方式和告警等级。
- `search_fields`：单主体模式默认搜索匹配规则内容；条件组合模式默认搜索规则名称，并仅追加服务端真实支持检索的条件字段或条件值；用户明确要求时追加备注。

不得承诺服务端不支持的完整表达式模糊搜索，也不得重复定义 `quick-filter-search` 的通用交互。

### 通用列表字段

将用户指定字段和 `rule_default_columns` 一并传给 `../templates/list.md`。用户字段优先；补充通用字段后必须告知。

规则业务通用字段基线：

| 顺序 | 字段 | 展示与行为 |
| ---: | --- | --- |
| 1 | 规则名称 | 条件组合模式默认作为主要识别字段；单主体模式仅在需求要求时出现 |
| 2 | 匹配规则内容 | 单主体模式显示具体对象值并支持复制完整值；条件组合模式显示可读摘要，并可查看完整表达式，不套用对象值复制交互 |
| 3 | 备注 | 无内容显示 `-` |
| 4 | 启用状态 | 逐条切换时需确认 |
| 5 | 创建者 | 创建账号 |
| 6 | 创建时间 | 完整时间，可排序 |
| 7 | 最近修改人 | 最后修改账号 |
| 8 | 最近修改时间 | 完整时间，可排序 |

没有规则名称时，“匹配规则内容”顺延为第一业务列。默认创建时间倒序，创建时间和最近修改时间执行真实服务端排序。条件列仅按能力追加：主体类型、处置方式、生效资产、有效期/过期状态、告警信息。选择列和操作列由 `../templates/list.md` 生成。

### 行操作

- 编辑打开编辑弹窗；删除和状态切换先确认，不跳转独立页面或无提示生效。

## 新增规则弹窗

点击“新增”打开业务命名的模态弹窗。通用字段顺序：

1. `启用状态`：必填，单选，默认启用。
2. `规则名称`：条件组合模式默认必填；单主体模式仅在需求明确时出现。
3. `匹配规则内容`：必填，按 `match_mode` 使用下方对应分支。
4. `命中结果`：结果固定时只外显业务效果；支持多种结果时提供选择并联动后续字段。
5. `过期时间`：条件字段；仅业务支持自定义有效期时显示。
6. `备注`：选填，单行输入。
7. `生效资产`：仅非全局固定生效时，在基础配置区之后使用独立模块。
8. `生成告警信息`：仅当前命中结果会生成告警时使用独立模块；存在生效资产模块时排在其后。
9. 其余字段：只按需求补充，不从参考模块照搬。

### 匹配规则内容

#### 单主体匹配

- 主体类型固定时不显示选择器，直接使用具体业务字段名；同一入口支持多种主体时显示“主体类型”并必填。
- 主体值使用带行号的多行输入，一行一个值，支持批量添加；其他通用字段作为本批规则的共享配置。
- 切换主体类型时同步更新字段名、说明、示例、条数、归一化、校验及条件字段；不适用字段立即取消校验且不提交残值。
- 忽略空行，并按业务约定归一化空格和大小写；客户端校验必填、格式、最大行数和同批重复并定位到行，服务端校验存量重复、保留对象及规则冲突，禁止静默丢弃。

#### 条件组合匹配

- 一条条件由“条件字段 + 操作符 + 值”构成；字段决定可用操作符、值组件、单值/多值和校验规则。
- 条件行和条件组使用 `IxProFormList` 承载新增、删除与嵌套结构；同一条件内“条件字段 -> 操作符 -> 值”的动态联动必须使用 `IxProFormDependency`，不得用手写监听或独立状态替代。
- `IxProFormDependency` 的 `names` 使用依赖字段路径数组；位于 `IxProFormList` 条件行内时使用本行局部依赖范围。默认插槽参数是对应字段的 `controlContext`，读取值时使用 `.value`；它只负责依赖渲染和重新校验，不得作为条件列表的数据容器。
- 一个条件组至少包含一条条件，组内关系支持 `AND/OR`；多个条件组通过组间 `AND/OR` 连接。只支持“条件组 -> 条件”两层结构，禁止无限嵌套。
- 提供“新增条件”和“新增条件组”；删除后不得留下空条件或空条件组。只有一个条件或条件组时，不展示无业务意义的连接关系。
- 切换字段或操作符时，清理不兼容的值、校验和提交残值；多值操作符按字段格式逐项校验。
- 客户端校验条件完整性、字段/操作符兼容性、值格式、数量上限、重复或明显矛盾条件；服务端校验语义重复、规则冲突和不支持的表达式。
- 整个条件表达式只提交为一条规则。不得把条件行当作批量规则，也不得套用“部分成功”语义。

### 命中结果分支

| 命中结果 | 业务含义 | 配置要求 |
| --- | --- | --- |
| `allow` | 命中后放通、跳过检测、加入信任或不再处置 | 外显具体放通效果，不显示拦截或告警配置 |
| `block` | 命中后拦截、隔离、阻断，或同时生成告警 | 定义处置方式；只有选择会生成告警的方式时显示“生成告警信息” |
| `detect` | 命中后记录、检测或生成告警，不执行拦截 | 明确记录与告警结果，不包装成黑类规则 |
| `custom` | 需求定义的其他结果 | 根据真实业务定义字段和联动，不继承白类/黑类默认值 |

固定一种结果时直接说明；存在多种结果时使用单选，并联动字段注册、校验和提交。

### 生效资产决策

- `fixed-global`：不显示生效资产模块；在匹配规则内容下方按 `../templates/form.md` 的“业务结果或影响范围”外显“该规则默认对全局资产生效”。
- `configurable`：独立模块标题为“生效资产”，完整复用“任务中心 -> 新增快速扫描任务 -> 任务对象”，不得简化为单个资产选择器。
- 数据契约：`scopeType: all | part`；指定资产时 `includeAssets` 必填，全部资产时清空；`excludeAssets` 始终可选。包含与排除均支持资产和资产组。
- 编辑需完整回显并纳入显隐、校验、dirty 和提交；失效或无权限资产不得静默清除。

### 过期时间决策

- 永久：不显示配置项；永久/自定义可选：显示单选，仅自定义时显示时间选择；固定有效期：只说明结果，不伪装成选项。
- 自定义时间需明确最小值、时区、当天边界和到期后的规则状态。

### 提交结果

- 单主体批量新增全部成功后关闭并刷新；部分成功返回数量及失败明细；全部失败保留输入供修改。
- 条件组合模式成功后关闭并刷新；失败时保留完整表达式并定位字段、条件或条件组错误。

## 编辑规则弹窗

- 行内编辑打开模态弹窗，只处理一条完整规则。
- 单主体模式的主体值及主体类型默认只读；更换主体应删除后新增。业务明确允许修改时，重新执行新增的格式、重复和冲突校验。
- 条件组合模式默认允许编辑完整表达式并重新执行全部联动、校验和冲突检查；接口不允许修改时需明确只读范围和替代流程。
- 可编辑通用字段包括启用状态、备注，以及按能力出现的命中结果、生效资产、过期时间和告警信息。
- 保存、取消和 dirty 执行 `../templates/form.md`；成功后保留列表查询、排序和分页，失败时保留输入并展示字段或冲突错误。

## 生成告警信息

仅当前命中结果会产生告警时显示，可包含告警名称、等级和描述；切换为不告警的结果后取消字段注册、校验和提交。

## 表单能力声明

新增和编辑弹窗固定向 `../templates/form.md` 返回：

```yaml
form_contracts:
  create:
    form_container: modal
    form_mode: create
  edit:
    form_container: modal
    form_mode: edit
```

单列对齐、分组与标题、动态字段、底部操作和 dirty 保护全部执行 `../templates/form.md`；单主体模式补充带行号多行输入，条件组合模式补充条件行、条件组和逻辑联动。本模型只传递前文确定的字段、模式分支和业务契约。

## 验收门禁

- 已明确 `match_mode`，页面、列表、校验和提交均使用同一模式；未把匹配规则内容继续等同为对象值。
- 列表一行对应一条完整规则；列表初始为空，无内置规则，且未引入策略优先级、复制、继承或分配冲突。
- 列表“匹配规则内容”按模式展示：单主体可复制完整值，条件组合可查看完整表达式；组合规则默认有稳定的规则名称。
- 新增和编辑均为弹窗并执行 `../templates/form.md`；编辑只处理一条完整规则。

# 全新策略模块业务模型 Reference

## 输入与返回契约

- 接收路由入口提供的结构化上下文包，不重新判断是否应复用安全策略。
- 仅在已确认存在独立策略对象或独立治理模型时执行。
- 负责新模块的信息架构、策略生命周期、列表、新增/编辑、复制和授权异常。
- 完成业务模型后由入口读取 `../templates/form.md`，不得自行提前选择表单组件。
- 返回模块位置、业务对象、治理模型、平台分区方式、页面结构、业务不变量、页面级交互契约、设计能力、参考证据、验收条件、回归范围、前置/后置确认项和自检结果。

## 执行边界与调用契约
- 先根据用户需求来确认要新增的策略在菜单架构哪个位置。如用户未明确输入，请先进行确认，得到确认后才能继续执行以下步骤
- 本 Reference 负责策略模型与页面级规则；“策略配置”内的通用表单结构、组件、交互与排版，由入口继续读取 `../templates/form.md` 完成。
- 不删除或改写下方原有规则；与本节冲突时，保留原规则并由路由结论决定适用范围。
- 除用户的需求和skill内容外，不能自由发挥，新增或修改未提及的内容

## 前置强制约束（最高优先级，100% 遵守）
1、所有组件必须取自 idux 组件库，禁止自定义组件；无对应组件或规则未定义时，禁止自行推演，需明确告知用户待确认项，确认后再继续。
2、组件默认高度 32px；通用表单规则以 `../templates/form.md` 为准，冲突优先级：业务专属规则 > 表单通用规则。
3、所有样式参照均以产品现有页面为准，不得自行演绎样式效果。
4、存在待确认点时，判断待确认点为前置确认点还是后置确认点。前置确认点要在方案输出前汇总确认，得到明确确认后才能开展生成。后置确认点先输出方案再统一汇总确认。


## 输出逻辑
0、先根据用户需求来确认要新增的策略在菜单架构哪个位置。如用户未明确输入，请先进行确认，得到确认后继续执行以下步骤
0.1、确认是否按“系统类型 × 资产类型”拆分策略列表。此项会改变列表、路由和数据边界，属于前置确认项；用户未明确说明时，必须先推荐并询问，不得自行默认拆分或不拆分。确认问题必须同时给出：
	•	推荐结果及业务依据，例如不同组合是否存在独立配置能力、分配范围或生命周期。
	•	若拆分，需要用户确认当前实际支持的组合；禁止自动生成尚未支持的系统或资产组合。
	•	若不拆分，直接采用单一策略列表，不显示平台标签，不按平台拆分列表路由和策略数据。

返回结构化结果：
```yaml
platform_partition:
  enabled: true | false
  supported_combinations: [] # enabled=true 时填写已确认组合
  routing_pattern: platform-tabs | single-list
```

分支规则：
	•	`enabled=true`：读取 `policy-management-existing.md`，仅执行其中“资产平台分区”的路由模式。顶部按已确认组合显示标签，每个标签拥有独立列表、查询条件、平台上下文及新增 / 编辑 / 返回链路；刷新或直接访问时保持当前组合，详情页继承来源组合。只复用路由结构，不得自动继承安全策略的 Windows 组合、分类、配置项和默认值。
	•	`enabled=false`：后续列表、搜索、优先级、分配对象和策略生命周期均在同一数据域内设计；不得为了视觉对齐安全策略而补充平台标签、平台筛选或平台参数。

1、判断是否默认有内置策略：此项为后置待确认点，输出方案后可以跟用户确认是否有内置策略
	•	产品必备功能（如升级、基础安全策略）：内置默认策略。内置策略的业务优先级永远最低，因此在策略列表中永远位于所有非内置策略之后；这是优先级语义的结果，不是独立的视觉置底规则
	•	内置策略禁止删除、禁用、调整优先级，悬浮提示对应原因；参照安全策略默认策略样式。任何搜索、筛选和排序交互均不得使其获得高于非内置策略的业务优先级
	•	非必备功能（如自定义规则、白名单）：无内置策略，列表初始为空状态

2、策略列表页：整体样式参照「策略中心 - 安全策略」列表页。

2.1 页面框架

策略列表统一采用 `quick-filter-search` 的基础列表结构，单条策略占一行。页面结构固定为：

```text
策略列表页
├── 页面头部
│   ├── 左侧：页面标题
│   └── 右侧：刷新
└── 列表主区
    ├── 表格头部
    │   ├── 左侧操作区：新增 → 删除 → 启用 → 禁用 → 优先级调整 → 资产适用策略检测（条件性）
    │   └── 右侧查询区：快速筛选 → 检索框（含批量检索）
    ├── 已选条件区（存在生效条件时展示）
    ├── 表格
    └── 分页及选中信息
```

	•	刷新固定在页面头部右侧，复用安全策略页面的刷新位置和样式，不得放入表格头部，不得重复生成第二个刷新入口。
	•	表格头部的左侧操作区与右侧查询区同一行展示；左侧操作区左对齐，右侧查询区右对齐，不得将检索框放到操作按钮之间或独立占用下一行。
	•	快速筛选与检索框必须组合生效；生效条件在表格头部下方的已选条件区回显，支持删除单项和清空全部。
	•	页面区域、容器、间距、表格起点及分页位置完整复用「策略中心 - 安全策略」真实页面，不得使用无业务作用的卡片或自行拼装另一套页面框架。

2.1.1 左侧操作区

	•	操作顺序固定为：新增 → 删除 → 启用 → 禁用 → 优先级调整 → 条件性的资产适用策略检测。
	•	新增与资产适用策略检测始终可点击；删除、启用、禁用和优先级调整依赖列表勾选，未勾选时禁用，悬浮提示「请先勾选对象再执行操作」。
	•	按钮名称只表达操作动作，固定使用「删除」「启用」「禁用」，不得显示为「批量删除」「批量启用」「批量禁用」；批量是勾选多条策略后执行的操作范围，不写入按钮名称。
	•	优先级调整使用下拉操作，默认包含「移动到」「置顶」；具体交互继续执行本 Reference 的优先级规则。
	•	当策略支持对非全部资产生效时，返回 `asset_applicability_check: { enabled: true, entity_type: strategy, label: 资产适用策略检测 }`；固定仅对全部资产生效时返回 `enabled: false` 且不显示按钮。
	•	资产检测按钮点击效果完整参照「策略中心 - 安全策略 - 资产适用策略检测」，交互由 `../templates/list.md` 执行；不得缩写、漏字或改为其他名称。
	•	内置策略禁止删除、禁用和调整优先级。对应行选择框或操作入口禁用时，悬浮必须说明具体原因，不得只呈现不可点击状态。
	•	工具栏不默认生成导入、导出；存在明确业务需求时再作为后置待确认项补充。

2.1.2 右侧查询区

```text
快速筛选 → 检索框（含批量检索）
```

	•	快速筛选字段默认包含：启用状态、创建时间、最近修改时间；扩展的业务枚举字段同步纳入快速筛选。
	•	检索框支持按名称、描述、分配对象、创建人进行关键字检索；批量检索是检索框的内部能力，不得设计成独立按钮。
	•	快速筛选在前、检索框在后，位置、间距、宽度和展开方式复用「策略中心 - 安全策略」真实页面，不得自行拼装筛选控件。
	•	执行检索或筛选后回到第一页，并保留当前排序；刷新页面数据时保留当前检索、筛选、排序和页码。

2.2 字段结构与顺序

字段从左到右固定顺序为：优先级 → 名称 → 描述 → 业务关键字段（可选扩展） → 分配对象 → 排除对象 → 生效资产 → 启用状态 → 创建时间 → 创建人 → 最近修改时间 → 操作列。

	•	除业务关键字段外，其余字段为必选，所有策略列表默认保留；业务关键字段为扩展项，按需新增，严格放置于「描述」与「分配对象」两列之间。
	•	分配对象、排除对象和生效资产必须作为完整的策略适用范围列组输出，不得只复用其中部分字段。
	•	优先级、生效资产等需要解释业务口径的字段，必须复用安全策略的表头标题与小 i 提示模式；列宽必须为表头文字、排序图标和小 i 预留空间，不得出现表头换行。
	•	分配对象 / 生效资产后加小 i 提示，分别解释「分配选中对象（不含继承）」「实际生效资产」；排除对象无值时统一显示「-」。
	•	启用状态：默认策略不可关闭，悬浮提示「默认策略不允许禁用」；非默认策略开关切换需二次确认。
	•	操作列默认包含：编辑、删除、复制。内置策略的删除入口禁用，悬浮提示「内置策略不支持删除」。

2.2.1 业务关键字段规则
触发条件（满足任一即可新增）
	•	同类型策略预计数量 ≥ 10 条，仅靠名称与描述无法快速区分核心配置差异
	•	策略存在高辨识度的核心枚举参数，管理员日常需快速识别（如防护等级、处置模式、采集范围）
数量与位置约束
	•	单列表最多扩展 6 个业务关键字段，避免列数过多导致横向滚动
	•	固定插入位置：「描述」列之后，「分配对象」列之前，前后顺序不可调整
字段选型原则：用户指明字段时，按用户给出的字段输出。否则按以下逻辑先挑选输出，输出后作为后置待确认项给用户确认。
	•	优先选择枚举型、状态型、数值型字段，不放置长文本、复杂配置字段
	•	优先选择全局统一、无歧义的核心业务属性，例如：防护等级、处置方式、采集事件数、策略类型
	•	禁止将低频、小众场景的参数放入列表字段，次要参数统一收敛至详情页
呈现与交互规范
	•	单值文本 / 选项类：直接展示文字，内容超长时单行截断，悬浮显示完整内容
	•	数值类：携带单位展示（如「5 类事件」「7 天有效期」）
	•	字段含义存在理解门槛时，列表表头后增加小 i 提示，说明字段定义
	•	字段无值 / 未配置时，统一显示「-」占位
	•	若字段为枚举值，默认在快速筛选区增加对应筛选维度；文本类字段支持关键字搜索

2.3 优先级展示与排序规则
	•	内部排序值与页面展示序号必须分离：内部字段可用于排序，页面必须展示连续的优先级序号，不得向用户展示 `999`、`MAX_VALUE` 等内部哨兵值。
	•	优先级数值 `1` 代表最高优先级，数值越小，业务优先级越高
	•	页面展示字段统一使用 `priorityRank` 语义；内置策略的展示序号始终等于当前数据域内策略总数。例如列表共 7 条策略，内置策略展示为 `7`。
	•	列表默认按业务优先级从高到低显示；对应数值排序为 `priority ASC`。默认激活的排序状态和表头排序指示必须可见
	•	「优先级」「创建时间」「最近修改时间」表头必须提供排序交互，不得仅在方案文字中声明“支持排序”而界面没有排序入口
	•	切换时间排序后，普通策略按所选时间顺序排列；内置策略仍保持最低业务优先级并位于所有非内置策略之后
	•	返回 `design_capabilities: [list, search, filter, sort]`，由入口读取 `../templates/list.md` 完成通用交互；参考证据为「策略中心 - 安全策略」真实列表页及项目既有表格实现
	•	策略支持非全部资产生效时，同时返回 `asset_applicability_check`，不得因需求未明确提及列表按钮而漏掉该能力

3: 新增策略详情页
3.1 容器与模块结构
	•	1、容器：统一使用下钻页面
	•	2、固定三大模块： 
	•	1）基本信息：配置内容参照「新增安全策略 - 基本信息」 
	•	策略名称：必填，默认空
	•	优先级：默认置于当前优先级 `1` 的策略之前，保存后按产品既有规则重排优先级编号；`1` 始终表示最高优先级，不允许产生两个含义冲突的 `1`
	•	策略描述：选填，默认空
	•	策略状态：开关，默认启用
	•	2）策略配置：业务自定义内容，业务模型完成后由入口读取 `../templates/form.md`，并跳过其容器决策
	•	3）分配资产：配置内容参照「新增安全策略 - 分配资产」 
	•	资产范围：单选（全部资产 / 指定资产），选指定资产时唤起资产选择器
	•	排除资产：资产选择器

3.2 布局逻辑
满足任一条件 → 分步骤呈现，分步骤效果参照「策略中心-安全策略-新增安全策略」；否则优先以单页面呈现，所有的内容都在同一个页面呈现，没有步骤条，仅为一个下钻页面。
	•	策略配置的内容超过12项
	•	用户特别提及，「基本信息」会新增配置项，且配置的内容会影响后续模块配置内容

3.3 底部操作区规则
操作栏吸底常驻：
	•	单页面：仅有「保存」「取消」按钮
	•	分步骤：上一步、下一步、保存、取消，参照安全策略样式

按钮交互细则：参照「策略中心-安全策略-新增安全策略」效果
	1）保存
	•	先校验格式：必填项为空 / 格式错误时，提示「存在不符合规则的配置项，请修改后再保存」
	•	校验通过弹出配置确认弹窗，参照「策略中心-安全策略-新增安全策略」效果：表单形式展示全部配置，顶部提示「以下是策略的所有配置信息，请确定后提交」
	•	点击确定：轻提示「保存成功」，返回列表页；点击取消：关闭弹窗，停留在当前页
	2）取消 / 返回
	•	有内容修改：弹出二次确认弹窗
	•	无内容修改：直接返回列表页，无弹窗
	3）上一步 / 下一步
	•	首步无「上一步」，末步无「下一步」
	•	当前步骤校验不通过时，点击下一步触发错误提示

3.4 防错机制
未保存状态下切换页面 / 关闭页面 → 弹出二次确认弹窗（同取消按钮逻辑）；点击确定则放弃修改并执行跳转，点击取消则留在当前页。

3.5 页面级交互契约输出

不得只把 3.3 和 3.4 保留为方案描述；必须转换为结构化 `interaction_contracts` 和 `acceptance_checks` 传回入口。每条交互至少包含：适用页面、前置状态、用户动作、预期结果、失败反馈。

新增策略默认至少返回以下契约：

- 未修改时取消或返回：直接回到列表，不弹确认。
- 修改任意已注册字段后取消或返回：弹出放弃修改确认；留在页面时保留已填内容，确认放弃时返回列表。
- 必填或格式错误时保存：显示统一错误提示，不提交保存请求。
- 校验通过时保存：先展示全部配置确认；取消确认停留当前页，确认提交后提示成功并返回列表。
- 有未保存修改时通过路由离开：执行与取消相同的二次确认。

必须按以下状态矩阵生成 `interaction_contracts`，不得只复用按钮处理函数后自行推断模式：

| 模式 | 保存确认 | 提交 | 关键默认值 | 保存后结果 |
| --- | --- | --- | --- | --- |
| 新增 | 展示全部配置 | 创建 | 推荐默认值 | 新增一条并返回列表 |
| 编辑 | 仅展示实际改动项，覆盖基本信息、策略配置、分配资产 | 更新原策略 | 原值回填 | 原策略更新并返回列表 |
| 复制 | 展示全部配置 | 创建，不得更新源策略 | 名称加 `_副本`、描述为空、启用、最高优先级 | 新增一条、源策略不变、内置策略仍最低 |

取消、返回和路由离开在三种模式下统一按 dirty 判断：无修改直接离开；有修改先确认，取消确认保留当前内容，确认放弃后执行原目标跳转。每个一级表单分组至少生成一条“修改字段 -> 确认弹窗包含该字段”的验收项。

前端实现中修改页面容器、步骤、表单分组、表单上下文、数据结构或路由守卫时，`regression_scope` 必须包含上述全部生命周期行为，禁止只验收本次新增的视觉或字段效果。

步骤4: 构建编辑策略页面，基于沿用新增策略详情页逻辑，仅存在以下差异：
	•	页面回填已有配置，面包屑显示「编辑策略」

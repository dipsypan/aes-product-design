## 1. 使用方式与输出契约

本 Reference 用于 AES PC 端对象详情的页面选型、信息组织和交互设计。Theme 或用户已锁定详情容器、正文组织或连续浏览能力时直接执行，不得重新选型；只有未锁定事项才按本文判断。病毒、日志、任务、事件、客户端等业务名称不是新的页面类型。

设计详情页时必须返回：

```yaml
detail_type: drawer-detail | drilldown-detail
content_organization: sections | tabs
sequence_navigation: enabled | disabled | not-applicable
drawer_width: 640 | 960 | user-specified
header_contract:
  drawer_title: 业务对象类型 + 详情 | not-applicable
  object_title: 当前对象实例的主标识
  summary_presentation: plain | emphasized
  presentation_reason: standard-summary | identity-context | relationship-context
  summary_fields: []
  exposed_actions: []
  more_actions: []
  noticeRegion: page-notice | none
  selection_reason: 说明容器、正文组织和概要表现的判断依据
body_modules:
  - module_id: ""
    content_type: descriptions | table | timeline | chart | raw-data | other
    pattern_requirements: []
reference_page: 真实参考页面
```

- `detail_type` 只有抽屉详情和下钻详情两类；`content_organization`、`sequence_navigation` 是结构能力，不得包装为新的页面类型。
- 抽屉必须返回 `drawer_width`；下钻页返回 `not-applicable`。
- 用户已明确容器、宽度或交互时，以用户要求为准；若与硬边界冲突，必须指出冲突和影响。
- Theme 已锁定容器或交互时，以锁定契约为准；若与硬边界冲突，返回 Theme，不得在本 Template 自行切换。

### 1.1 与 Common Design 的类型映射

本 Reference 对 AES 详情页的容器、概要区、正文组织、连续浏览和关闭方式采用 `override`。Common Design 中对应的页面类型只作为概念映射，不得覆盖本文件的 AES 规则：

| Common Design 页面类型 | AES 详情类型 | 说明 |
| --- | --- | --- |
| `page-detail-drawer` | `drawer-detail` | 抽屉是容器类型，不因病毒、日志、任务等对象名称拆出新页面类型 |
| `page-detail-drilldown` | `drilldown-detail` | 下钻是独立路由的详情容器 |
| `page-detail-log` | `drawer-detail` 或 `drilldown-detail` | 日志是业务对象/内容视图，按任务复杂度和路由需求选择容器，不作为 AES 独立页面类型 |

以下 AES 规则优先于 Common Design 的默认详情规则：概要区默认采用 `plain`，不强制使用 `IxCard`；只读抽屉默认通过右上角关闭，不生成空白 Footer；连续浏览是可复用的详情能力，不限定为日志页面。

Common Design 仍可补充本 Reference 未定义的通用组件 API、导航适配和基础可访问性要求；补充内容不得改变上述容器、页面类型映射和 AES 详情结构。

## 2. 容器选型

### 2.1 两类详情

| 类型 | 核心定位 | 适用条件 | 典型参考 |
| --- | --- | --- | --- |
| `drawer-detail` | 保留父页上下文，快速查看或轻量处理 | 信息量中等、任务短、详情链路不深、需要连续查看列表记录 | 病毒详情、日志详情、任务详情抽屉 |
| `drilldown-detail` | 进入独立空间完成深度理解或处理 | 信息多、任务复杂、需要独立路由或多模块协作 | 安全事件详情、告警链详情、任务中心任务详情、客户端详情 |

### 2.2 按顺序判断

1. 详情链路达到 3 级，使用下钻详情。
2. 包含复杂长表单、多步骤配置、富文本编辑、需要宽画布协同操作的图表与明细表组合，或单模块超过 3 屏且无法拆分，使用下钻详情。
3. 需要独立 URL、浏览器前进后退、新标签页打开、分享定位或刷新恢复，使用下钻详情。
4. 需要频繁对照父列表、连续查看多条记录、快速标记或轻量处置，使用抽屉详情。
5. 低频深度处理、高风险编辑或不可逆任务，使用下钻详情；高频低风险查看和短操作，使用抽屉详情。
6. 仍无法确定时，判断用户任务能否在抽屉内独立完成：能够保留父页上下文并完成快速查看或轻量处理时选抽屉；需要离开父页进行沉浸式处理时选下钻。

- Tab 数量不是容器选型条件。抽屉可以包含 2 个以上 Tab；根据内容复杂度、任务深度、父页上下文依赖和路由需求选择容器。

### 2.3 能力边界

| 判断项 | 抽屉详情 | 下钻详情 |
| --- | --- | --- |
| 父页上下文 | 保留 | 离开父页，但返回时恢复父页状态 |
| 详情层级 | 一级详情为主，最多扩展 1 层轻量子抽屉 | 支持更深的信息链路 |
| 正文组织 | 分区或多个 Tab | 分区或多个 Tab |
| 操作复杂度 | 查看和少量轻操作 | 深度分析、复杂配置、高风险操作 |
| 路由能力 | 通常不提供独立 URL | 必须使用独立路由 |
| 退出方式 | 右上角关闭；连续浏览可有底部关闭 | 返回上级，不使用“关闭页面” |

- 禁止连续嵌套超过 2 层抽屉。
- 二级内容复杂或属于独立任务时，从一级抽屉跳转下钻页。
- 查看与编辑复杂度差异明显时，查看使用抽屉，编辑跳转下钻页。
- 同一列表、同类对象、同一层级必须使用一致的详情容器。

## 3. 通用页面结构

抽屉和下钻页共享以下内容结构：

```text
详情内容
├── 容器导航区
│   ├── 抽屉：业务对象类型 + 详情                         关闭 ×
│   └── 下钻：返回入口 / 面包屑
├── 顶部概要区（横向布局，整体一般不超过 2 行）
│   ├── 左侧对象区（弹性宽度）
│   │   ├── 第 1 行：对象主标题 + 身份/等级/状态标签
│   │   └── 第 2 行：概要字段 1 │ 概要字段 2 │ 概要字段 3
│   └── 右侧操作区（固定在右侧，仅一行）
│       └── 操作 1 + 操作 2 + 更多
├── 页面提示区（按需，由 page-notice Pattern 决定）
└── 正文内容区
    ├── 分区平铺
    └── 或 Tab 切换
```

- 顶部概要区是一个横向父容器：左侧对象区可伸缩，右侧操作区固定宽度。
- 页面存在授权、风险、影响范围或其他业务提示时，预留 `noticeRegion`；提示条的展示条件和内容读取 `../04-patterns/page-notice.md`。
- 对象主标题、标签、概要字段均在左侧；业务操作均在右侧，不得混排。
- 左侧对象区一般不超过 2 行：第一行识别对象，第二行完成关键判断。
- 不得增加第三行概要字段。放不下的字段进入正文。
- 右侧操作始终横向排列，不得因标题或字段过长换到概要字段下方。

## 4. 顶部标题区与对象概要区

### 4.1 抽屉容器标题

- 抽屉标题固定使用“业务对象类型 + 详情”，例如“病毒详情”“事件详情”“任务详情”“规则详情”。
- 业务对象类型表示对象类别，不是当前记录的实例名称。
- 禁止只写“详情”“查看详情”，也不得用当前记录名称代替容器标题。
- 当前对象实例名称放在对象概要区第一行。

### 4.2 对象标题和左侧信息

- 左侧对象区第一行必须以当前对象实例的主标识为视觉主体，例如病毒名称、事件名称、任务名称或规则名称。
- 主标题使用比普通概要字段更高的视觉层级。无存量基准时使用 `14px`、`font-weight: 600`；同模块已有统一标题规范时沿用已有规范。
- 状态、等级、类型标签与主标题横向排列，可以位于标题前方或后方，但不能替代或削弱主标题。
- 图标只用于辅助识别对象类型，不能代替文本标题；主标题过长时单行省略并通过 Tooltip 展示完整内容，不得挤压右侧操作区。
- 实例没有自然名称时，使用最稳定、最可识别的业务主键作为主标题，不得显示空标题。

### 4.3 概要字段

- 第二行只放用户进入详情后首先用于识别、判断或处置的关键字段。
- 字段横向排列，一般控制在 3 至 5 个；字段较短且容器充足时可以适当增加，但不得形成第三行。
- 字段按“身份/范围 → 状态/结果 → 关键时间”的判断顺序组织，而不是照接口字段顺序罗列。
- 长描述、原始日志、完整路径、备注历史和低频字段进入正文。
- 空值统一显示 `-`；零值必须显示 `0`，不得按空值处理。

### 4.4 右侧操作

- 操作区固定在概要区右侧，仅一行横向排列。
- 最多外显 2 个业务操作；超出部分收入“更多”菜单。
- “更多”不计入 2 个业务操作上限，使用省略号图标并提供 Tooltip。
- 外显顺序按当前任务频率和重要性排列；危险操作不得仅因重要而默认外显，禁用操作必须展示具体原因。
- 操作执行后更新当前详情，并同步父列表；不改变当前查询上下文。

### 4.5 概要区背景

概要区只有两种表现：`plain` 和 `emphasized`。背景由内容语义决定，不得作为任意视觉选项。

#### `plain`：标准概要，默认使用

- 用于“对象主标题 + 标签 + 横向关键字段 + 操作”的标准对象概要。
- 不设置独立底色和装饰性卡片，直接在详情内容背景上排布。
- 信息通过标题层级、字段间距和正文分隔建立层次。
- 参考病毒详情。

```text
┌──────────────────────────────────────────────────────────┐
│ [高危] [木马]  Trojan.Win32.Agent       [处置] [标记] […] │
│ 场景：文件检测 │ 首次发现：… │ 状态：待处置 │ 终端：PC-01 │
└──────────────────────────────────────────────────────────┘
```

#### `emphasized`：语义聚合，满足条件才使用

- 仅用于必须被整体理解的身份上下文或关系上下文。
- 身份上下文是图标、名称、状态、描述等共同表达一个不可拆分的当前对象身份，并且正文依赖该身份上下文理解。
- 关系上下文是源对象、行为、目标对象、资产或关联结果组成的关系链，例如“进程 → 行为 → 目标对象”。
- 整块使用统一的中性浅色信息背景、`2px` 圆角和平台标准内边距；新页面不使用渐变背景。
- 参考日志详情的关系上下文；任务详情现有蓝色渐变属于历史实现，新设计应改用中性浅色背景或退回 `plain`。

```text
┌──────────────────────────────────────────────────────────┐
│ 浅色语义背景                                             │
│ [源进程 explorer.exe]  →  [访问行为]  →  [目标文件 A]    │
│ 关联资产：PC-01                         关联事件：事件 01 │
└──────────────────────────────────────────────────────────┘
```

以下情况不能作为增加背景的理由：字段较多、希望页面更丰富、其他页面使用了底色、仅需区分概要和正文。

## 5. 正文组织形式与布局

先选择正文组织形式，再执行对应布局规则。`sections` 是默认形式；Tab 用于解决内容过多或任务相互独立，不用于装饰页面。

### 5.1 第一步：选择平铺或 Tab

“正文内容模块”是有独立业务标题和完整内容的一组信息，例如执行信息、关联对象、处理结果；字段行不是独立模块。

1. 只有 1 个正文内容模块时，直接使用 `sections` 平铺，禁止生成只有一个 Tab 的标签页。
2. 有 2 个及以上模块时进入组织形式判断，仍默认使用 `sections` 平铺。
3. 只有平铺后内容明显过多，或模块属于用户不会连续阅读的独立任务/数据视图时，才使用 `tabs`。

以下任一情况成立，可将 2 个及以上模块组织为 Tab：

- 平铺后需要长距离滚动，用户难以快速定位目标模块。
- 各模块是相互独立的任务、数据集或分析视角，用户通常一次只查看其中一个。
- 各模块本身内容较重，分别包含表格、时间线、图表、原始数据或独立操作。
- 同一数据需要在结构化详情、原始日志等互斥视图间切换。

模块较多、但内容短且需要连续阅读时仍使用平铺；不得因模块达到某个数量直接使用 Tab。Tab 数量也不得参与抽屉与下钻页的容器选型。

```text
正文内容模块数量
├── 1 个 → 平铺
└── 2 个及以上 → 默认平铺并判断
    ├── 内容可在合理滚动范围内连续阅读 → 平铺
    └── 内容过多，或模块为独立任务 / 独立视图 → Tab
```

### 5.2 第二步：执行平铺布局

- 按用户阅读顺序纵向排列模块，标题使用明确业务名称，不使用“其他信息”“更多信息”。
- 分区标题参考“任务中心 - 任务详情 - 任务信息”抽屉：`14px`、`font-weight: 600`、默认行高 `36px`；左侧显示 `2px × 12px` 蓝色竖线并垂直居中。
- 竖线使用平台主色，AES 基准为 `#1c6eff`；同模块已有统一 Token 时使用对应 Token。
- 分区之间禁止使用分割线，以前一分区内容和下一标题之间默认 `16px` 的垂直间距建立层次。
- 同类字段使用描述列表，集合数据使用表格，过程和关联关系使用对应组件。
- `content_type=table` 时，将 `table-management` 写入该模块的 `pattern_requirements`，并传递 `host_template=detail`、`table_role=embedded`、抽屉宽度或正文可用宽度；不得先调用 List Template，也不得由 Table Pattern 重新决定详情容器、分区或 Tab。
- 分区内容不得套装饰性卡片；背景、边框和阴影不能代替标题与间距。

### 5.3 第二步：执行 Tab 布局

- 统一使用 `@idux-vue2/components` 的 `IxTabs`，设置 `type="line"`、`placement="top"`；不得使用卡片型或分段型 Tab 作为详情正文导航。
- 使用 `dataSource` 定义稳定且唯一的 `key` 和明确的 `title`，通过 `:selectedKey.sync` 管理选中项，通过 `#content="{ key }"` 渲染内容；不得使用不存在的 `IxTabPanel`。
- Tab 名称直接表达内容或任务，例如“结构化详情 / 原始日志”“任务信息 / 执行记录”；少量字段不能独立成为 Tab。
- 抽屉允许使用 2 个以上一级 Tab。Tab 溢出时保留 `showAllTabsPanel` 能力，通过组件的全部标签入口访问，不压缩文字、换行或缩小字号。
- Tab 内允许按 5.2 使用少量平铺分区，但不得继续嵌套主要 Tab。
- 切换 Tab 保留已加载数据和局部状态；连续切换到另一条记录时回到默认 Tab。下钻页需要直接定位时将选中 Tab 写入路由。

## 6. 抽屉详情参考基准

### 6.1 宽度

- 默认宽度为 `640px`，用于单列字段、基础查看和少量分区。
- 宽抽屉为 `960px`，用于横向概要字段较多，或正文包含表格、关系内容、图形或多个 Tab。
- 用户可以根据明确的信息内容量指定其他宽度，最大不得超过 `1200px`。
- 合理内容在 `1200px` 内仍无法承载时，重新判断为下钻详情，不继续加宽。
- 同模块、同类型抽屉宽度保持一致，不因单条数据长短动态改变。

### 6.2 连续浏览抽屉

用于从当前列表结果中连续查看多条记录，通常为非模态抽屉。

```text
父列表（保留可见和当前查询状态）     ┌──────────────────────────────┐
                                    │ 病毒详情                关闭 × │
                                    ├──────────────────────────────┤
                                    │ 对象标题 + 标签       横向操作 │
                                    │ 概要字段 1 │ 字段 2 │ 字段 3 │
                                    ├──────────────────────────────┤
                                    │ 分区正文，或多个 Tab          │
                                    │                              │
                                    ├──────────────────────────────┤
                                    │ [上一个] [下一个] [关闭]      │
                                    └──────────────────────────────┘
```

- `sequence_navigation: enabled`，底部固定显示“上一个 / 下一个 / 关闭”。
- 上一个、下一个以打开抽屉时列表的搜索、筛选、左树范围和排序结果为序列。
- 第一条禁用“上一个”，最后一条禁用“下一个”，仅一条时两者均禁用；按钮位置保持稳定。
- 切换期间禁用上一个和下一个，保留抽屉骨架或加载态，不先闪空。
- 快速连续点击时，仅最后一次请求可以更新详情，避免旧请求覆盖新记录。
- 切换成功后重置正文滚动位置、默认 Tab、展开项、局部选择和错误状态。
- 切换失败时保留原记录和原序号，并提示失败，不得显示半条新数据。
- 当前记录被删除后优先展示下一条；没有下一条时展示上一条；序列为空时关闭抽屉。
- 用户改变父列表搜索、筛选、左树、排序或分页时关闭抽屉，避免切换序列与列表不一致。
- 不同时打开多个详情抽屉进行对比；需要对比时使用下钻页的新标签页能力或专门的对比功能。

### 6.3 单记录抽屉

用于临时查看一条记录，不承担列表连续浏览，通常为模态抽屉。

```text
┌────────────────────────────────────────────┐
│ 任务详情                            关闭 × │
├────────────────────────────────────────────┤
│ 任务名称 + 类型标签                 状态/操作 │
│ 执行对象：… │ 创建时间：… │ 发起人：…       │
├────────────────────────────────────────────┤
│ 执行信息                                   │
│ 字段 …                                     │
│                                            │
│ 任务信息                                   │
│ 字段 …                                     │
└────────────────────────────────────────────┘
```

- `sequence_navigation: disabled`，不显示上一个和下一个。
- 只读详情通过右上角关闭，不生成空白底部操作栏。
- 存在必须完成的业务操作时才增加固定底部操作区；关闭不重复作为主业务按钮。
- 点击遮罩是否关闭遵循平台抽屉规范；存在编辑态或未保存输入时禁止遮罩关闭，并提供离开确认。

### 6.4 抽屉二次结构

抽屉只允许以下四种结构组合，用于选参考逻辑，不是四种页面类型：

| 连续浏览 | 正文组织 | 适用说明 | 参考 |
| --- | --- | --- | --- |
| 有 | 分区 | 快速逐条查看，内容属于同一判断任务 | 病毒详情 |
| 有 | Tab | 快速逐条查看，不同数据视图相互独立 | 日志详情 |
| 无 | 分区 | 单条轻量详情，按模块顺序阅读 | 任务详情抽屉 |
| 无 | Tab | 单条详情存在两个独立内容任务 | 按规则组合，优先复用同模块实现 |

## 7. 下钻详情参考基准

### 7.1 分区下钻页

```text
┌──────────────────────────────────────────────────────────┐
│ ‹ 返回 / 面包屑                                          │
├──────────────────────────────────────────────────────────┤
│ 对象主标题 + 标签                      [操作 1] [操作 2] […] │
│ 概要字段 1 │ 概要字段 2 │ 概要字段 3 │ 概要字段 4          │
├──────────────────────────────────────────────────────────┤
│ 模块一                                                    │
│ 内容                                                      │
├──────────────────────────────────────────────────────────┤
│ 模块二                                                    │
│ 内容                                                      │
└──────────────────────────────────────────────────────────┘
```

- `sequence_navigation: not-applicable`，不使用上一个、下一个或关闭。
- 使用返回入口和浏览器导航；返回后恢复父列表搜索、筛选、排序、分页和滚动位置。
- 模块属于同一深度处理任务且需要顺序理解时采用分区平铺。
- 顶部概要和关键操作在滚动后是否吸顶，沿用同模块既有页面；无存量基准时不额外吸顶。

### 7.2 Tab 下钻页

```text
┌──────────────────────────────────────────────────────────┐
│ ‹ 返回 / 面包屑                                          │
├──────────────────────────────────────────────────────────┤
│ 对象主标题 + 标签                      [操作 1] [操作 2] […] │
│ 概要字段 1 │ 概要字段 2 │ 概要字段 3 │ 概要字段 4          │
├──────────────────────────────────────────────────────────┤
│ [总览] [关联告警] [攻击分析] [处置记录]                   │
├──────────────────────────────────────────────────────────┤
│ 当前 Tab 的独立内容、操作和状态                           │
└──────────────────────────────────────────────────────────┘
```

- 多个独立任务、数据集或分析视角使用 Tab；是否采用下钻页仍由任务复杂度、上下文依赖和路由需求决定，与 Tab 数量无关。
- 默认 Tab 必须对应最高频的首要任务，不机械命名为“基本信息”。
- 需要直接定位时，将当前 Tab 写入路由；刷新和前进后退应恢复当前 Tab。
- Tab 切换不重复请求稳定数据；时效性数据按业务刷新策略更新。
- 页面级操作放在顶部右侧；只作用于当前 Tab 的操作放在 Tab 内容工具区，不能混淆作用范围。

### 7.3 下钻二次结构

| 正文组织 | 适用说明 | 参考 |
| --- | --- | --- |
| 分区 | 信息多但属于一个连续处理任务 | 按任务中心详情的连续模块逻辑组织 |
| Tab | 多个独立分析或管理任务 | 安全事件详情、客户端详情 |

## 8. 状态、异常与边界

### 8.1 加载与失败

- 首次加载使用与页面结构匹配的骨架或加载态，避免空白容器。
- 概要与正文可以分开加载；概要失败时不得显示错误对象标题，正文局部失败只替换对应分区或 Tab。
- 整体失败显示重试入口，并保留退出或返回能力。
- 操作成功后刷新受影响区域并同步父列表；失败时保留当前内容和用户位置。

### 8.2 空值与长内容

- 普通空字段显示 `-`；整个模块没有数据时显示模块级空状态，不罗列整屏 `-`。
- 长标题、路径、哈希、ID 和描述必须提供省略、换行、复制或 Tooltip 中合适的一种完整查看方式。
- 原始 JSON、日志和代码类内容使用等宽字体，支持复制；数据量大时使用虚拟滚动或按需加载。
- 字段和值不得与操作区重叠，不得因国际化长文案改变固定操作位置。

### 8.3 权限与操作

- 无查看权限时不进入详情；局部无权限时在对应模块展示明确状态。
- 无操作权限的动作按平台规则隐藏或禁用；禁用时必须说明原因。
- 高风险操作必须二次确认，成功与失败均给出明确反馈。
- 编辑存在未保存内容时，关闭抽屉、返回、切换 Tab 或跳转前均按影响范围提供离开确认。

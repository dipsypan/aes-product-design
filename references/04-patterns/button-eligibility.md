# AES 操作按钮可执行性 Pattern

> **归属：AES Product Design。** 本 Reference 是 AES（深信服下一代端点安全）产线专属 Pattern，不作为 Common Design 的通用交互规范。
> `Coverage: extend`
> 本文明确规定的 AES 方案优先；未覆盖事项由 `prd-design-code` 按 Coverage 调用 Common Design 补充。

## 使用边界

本 Reference 处理操作执行前的对象判断、按钮状态和范围反馈。

- 包含：对象是否可执行、按钮激活可用或不可用、部分执行和被排除对象的提示。
- 不包含：操作权限与入口显隐、二次确认、请求失败、执行结果和任务状态。

## 判断流程

先识别：

- 已选对象
- 可执行对象
- 不可执行对象及原因
- 操作是否允许部分执行

```text
操作依赖已选对象，但当前未选择
→ 按钮不可用，采用 disabled 状态

已选对象全部可执行
→ 按钮可用状态，作用于全部已选对象

已选对象部分可执行
├─ 允许部分执行 → 按钮可用，只作用于可执行对象
└─ 不允许部分执行 → 按钮不可用，采用 disabled 状态

已选对象全部不可执行
→ 按钮不可用，采用 disabled 状态
```

其他业务前提不满足时，按不可执行处理。

## 部分执行规则

仅在以下条件同时满足时允许自动跳过：

- 各对象可以独立执行，不要求整体成功。
- 跳过部分对象不会破坏业务状态或操作目标。
- 不可执行对象及原因可以在执行前明确识别。
- 仍有可执行对象。

以下情况不自动跳过：

- 操作要求全部对象保持一致。
- 缩小执行范围会改变用户的核心目标。
- 用户需要先处理原因或重新选择对象。
- 只能在请求执行后才能确定不可执行。

## 反馈方式

### 按钮不可用

- 悬停必须说明不可用原因。
- 已有气泡或下拉说明时，直接在原有承载中补充原因，不叠加 Tooltip。
- 没有已有承载时，使用 Tooltip。
- 原因应具体；存在明确解决方式时，同时说明下一步。

### 部分执行

- 原因单一、用户无需逐条处理时，Toast 提示跳过数量和原因即可。
- 用户需要确认范围、处理原因或进行审计时，提供可展开的跳过明细。
- 跳过反馈应在提交或执行前可见；执行后的失败属于结果反馈，不在本文处理。

## 示例
| 页面场景 | 操作 | 场景 | 结果 |
| -- | -- | -- | -- |
| 任务中心 > 任务计划 | 删除 | 未选择对象 | 按钮不可用，悬停按钮提示先勾选数据 |
| 病毒防护 | 结束进程 | 全部对象不可执行 | 按钮不可用，在已有气泡中说明原因 |
| 任务中心 > 任务记录 | 再次下发 | 任务已完成 | 按钮不可用，Tooltip 说明无需重复执行 |
| 病毒防护 | 隔离文件 | 部分对象可执行 | 按钮可用，点击后 Toast 提示跳过了不支持操作的数据 |

## 输出契约

```yaml
button_eligibility:
  state: enabled | disabled
  executable_objects: []
  excluded_objects: []
  excluded_reasons: []
  partial_execution: allowed | disallowed | not-applicable
  feedback: none | disabled-reason | skipped-summary | skipped-details
```

## 业务要求

- 未选择对象、全部不可执行或不允许部分执行时，按钮不可用。
- 全部可执行或允许部分执行时，按钮可用且作用范围明确。
- 不可用按钮不能触发操作，悬停仍能显示原因。
- 已有悬停承载时不会出现重复提示层。
- 部分执行时，用户能在提交或执行前知道跳过数量、原因或明细。

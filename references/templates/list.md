# AES产线下一代端点安全产品通用列表设计 Reference

## 目录

- 页面判断：列表结构、业务交互、搜索筛选模式
- 页面整体结构
- 概览区与左树区域
- 表格头部操作区
- 搜索与源、展示、排序、操作和列设置
- 分页与选中信息筛选
- 表格：字段来
- 页面状态
- 实现与证据
- 输入输出与准出自检

## 1. 页面判断

设计前分别确定 `list_type`、`business_type` 和 `search_mode`，三者相互独立。

### 1.1 列表结构类型

| 类型 | 页面结构 | 适用条件 | 参考页面 |
| --- | --- | --- | --- |
| `basic-list` | 操作查询区 + 表格 + 分页 | 普通数据查询与操作 | 告警链、安全事件 |
| `overview-list` | 概览区 + 基础列表 | 需要先查看汇总状态，再进入明细 | 任务中心 |
| `tree-list` | 左树 + 基础列表 | 数据需要按稳定层级范围管理 | - |
| `tree-overview-list` | 概览区 + 左树 + 基础列表 | 同时需要层级范围和汇总状态 | 客户端列表 |

- 默认使用 `basic-list`。
- 只有存在明确汇总指标时增加概览区。
- 只有存在组织、分组、资产等稳定层级时增加左树。
- 快速筛选不能作为增加左树的理由。
- 不得照搬参考页面中与当前需求无关的区域。

### 1.2 业务交互类型

| 类型 | 用户主任务 | 行主交互 |
| --- | --- | --- |
| `business-browse` | 浏览、判断、进入详情 | 名称进入详情；真实页面支持时允许整行进入 |
| `config-manage` | 新增、编辑和维护配置 | 名称或操作列进入编辑，禁止整行进入 |
| `operation-closed` | 在列表内完成查看和处置 | 无整行主交互，从字段或操作列触发 |

字段自身有点击操作时，字段交互优先于整行交互。

### 1.3 搜索筛选模式

| 模式 | 页面形态 | 适用场景 | 参考页面 |
| --- | --- | --- | --- |
| `condition-search` | 表格上方独立高级检索区 | 字段多、条件组合复杂 | 安全事件、病毒列表 |
| `quick-filter-search` | 右侧快速筛选按钮 + 检索框 | 筛选维度较少且固定 | 任务中心、安全策略 |

选择规则：

1. 存量模块保持现有模式。
2. 日志、事件、告警、病毒等分析场景优先使用 `condition-search`。
3. 策略、规则、任务等管理场景优先使用 `quick-filter-search`。
4. 两种模式互斥，不得同时生成。
5. 平台高级检索对应 `SeerdTableContainer.search.conditionSearch`。
6. 业务 Reference 必须返回搜索模式、检索字段和默认条件。

职责边界：

- 业务 Reference 只决定 `search_mode`、业务检索字段、快速筛选字段和默认条件。
- 本 Reference 统一决定对应模式的页面位置、组件能力、组合查询、条件回显、清空、重置、刷新和分页联动。
- 业务 Reference 不得重复定义 `quick-filter-search` 的通用交互；存在业务专属限制时只返回差异项。

## 2. 页面整体结构

列表页按以下结构组织：

```text
列表页
├── 页面头部（右侧刷新）
├── 概览区（可选）
└── 工作区
    ├── 左树（可选）
    └── 列表主区
        ├── 搜索与操作区
        ├── 已选条件区（按模式展示）
        ├── 表格
        └── 分页及选中信息
```

`condition-search`：

```text
列表主区
├── 高级检索区
├── 操作与辅助工具区
├── 表格
└── 分页及选中信息
```

`quick-filter-search`：

```text
列表主区
├── 表格头部
│   ├── 左侧操作区
│   └── 右侧：快速筛选 → 检索框（含批量检索）
├── 已选条件区
├── 表格
└── 分页及选中信息
```

- 高级检索不得压缩成快速筛选按钮和普通输入框。
- 快速筛选模式不得额外生成独立高级检索区。
- 页面区域不得使用无业务作用的卡片嵌套。
- 容器、间距和区域布局优先复用真实参考页面。

### 2.1 列表顶部提示条

- 存在业务效果、影响范围或容量说明时，在页签下方、表格上方使用 `IxAlert banner type="offline"`。
- 复用对象白名单位置和尺寸：`margin: -8px -12px 8px`，高度保持 32px。
- 主说明与详情入口在左侧单行展示，容量等附加信息右对齐，不得换行或掉到下一行。
- 同级页签的提示条边界和下方表格起点必须一致；没有明确业务说明时不生成提示条。

## 3. 概览区

- 概览只展示与当前列表判断有关的汇总指标。
- 默认展开并支持收起；收起不影响列表查询。
- 点击可筛选指标时更新列表条件，选中状态与筛选状态同步。
- 切换左树节点后，概览和表格使用同一范围重新加载。
- 概览请求失败不得阻塞列表。
- 概览和表格分别处理加载、空和异常状态。

### 3.1 概览展开与收起

- 所有概览区的展开收起按钮统一参考病毒列表，放在页面头部操作区并使用平台默认按钮样式。
- 展开时使用 `eye-invisible` 图标和「隐藏概览」，收起时使用 `eye` 图标和「显示概览」；图标尺寸为 16px。
- 不得自行改用其他按钮样式、图标、开关或折叠把手。
- 收起只改变概览区可见性，不清除筛选条件、不重置分页；再次展开时恢复当前查询状态。

## 4. 左树区域

- 左树用于限定组织、分组、资产等稳定范围，不代替普通筛选。
- 默认节点由业务定义；未定义时复用参考页面规则。
- 切换节点后重置到第一页，并重新加载概览和表格。
- 树搜索只搜索树节点，不搜索表格数据。
- 左树、概览和表格必须共享同一范围标识。
- 左树必须覆盖加载、无节点、搜索无结果和失败状态。
- 树宽度、折叠和节点交互复用已有实现。

## 5. 表格头部操作区

### 5.1 左侧操作区

#### 操作排列

- 新增使用主按钮样式，位于操作区首位，不收入下拉菜单。
- 批量操作按钮外放不超过 7 个，超出部分收入「批量操作」菜单。
- 其他操作按使用频率从高到低排列。
- 危险或不可逆操作是否外放、是否二次确认，由业务 Reference 定义。
- 外放按钮名称只表达操作动作，使用「删除」「启用」「禁用」等动作名称，不得显示为「批量删除」「批量启用」「批量禁用」；批量是勾选多条对象后执行的操作范围，不写入单个按钮名称。只有收纳多个操作的菜单入口可以命名为「批量操作」。

#### 资产适用检测

- 业务 Reference 声明 `asset_applicability_check.enabled=true` 时，在左侧操作区增加检测按钮，位于对象管理操作之后、导入/导出之前；该按钮不依赖列表勾选并始终可点击。
- 策略列表固定命名「资产适用策略检测」，规则列表固定命名「资产适用规则检测」。仅当该类策略或规则支持对非全部资产生效时声明；固定全局生效时不得出现。
- 点击后完整复用「安全策略列表 -> 资产适用策略检测」的检测容器和流程：检索并选择资产、展示该资产适用的策略或规则、标识实际生效项。只替换业务实体、结果字段和接口映射，不自行设计另一套弹窗。
- 返回 `asset_applicability_check`：`enabled`、`entity_type: strategy | rule`、`label`、`reference`、资产检索契约、结果列与接口映射。

#### 按钮状态

| 操作类型 | 未勾选时 |
| --- | --- |
| 新增、导入、条件性的资产适用检测 | 可点击 |
| 删除、启用、禁用等对象操作 | 禁用 |
| 导出 | 可点击；未勾选导出全部，勾选后导出选中对象 |

- 依赖勾选的操作在未勾选时必须禁用。
- 悬浮禁用按钮时提示：`请先勾选对象再执行操作`。
- 勾选后只激活当前选择范围允许执行的操作。
- 勾选、取消和清空后，按钮状态实时更新。
- 所有禁用控件必须同时返回明确的 `disabled_reason`，覆盖表格头部按钮、行操作、状态开关、下拉菜单项和选择框；不得只设置不可点击而不解释原因。
- 禁用原因必须对应当前对象与当前操作，例如「内置策略不支持删除」「默认策略不允许禁用」；不得用无关的统一提示覆盖业务限制。
- `disabled_reason` 必须通过真实悬浮交互可见；仅在方案文字、代码注释或不可触达的 DOM 中存在不算完成。

#### 勾选数量限制

- 默认不限制勾选数量。
- 选中后持续展示已选数量和清空入口，效果参考客户端列表。
- 存在性能限制时，由业务或技术提供上限 `X`，不得自行设置。
- 表头批量选择超过上限时提示：`最多勾选 X 条数据，将按顺序选择前 X 条数据`；确认后选择前 `X` 条，取消后保持原选择。
- 逐条勾选达到上限后不再加入新对象，并提示：`已达到勾选数量上限（X 个），请先移除已选对象后再继续选择`。

#### 不支持操作的对象

- 只有一个批量操作时，不满足条件的对象禁止勾选并说明原因。
- 存在多个批量操作时允许统一勾选；执行时跳过不满足当前操作条件的对象。
- 跳过对象必须计入失败结果并展示原因，不得静默忽略。

#### 批量操作反馈

- 执行前明确操作对象数量；高风险操作按业务规则二次确认。
- 全部成功：提示成功数量。
- 部分失败：提示 `成功 X 个，失败 Y 个`，并展示失败对象和原因。
- 全部失败：明确提示失败，并展示全部失败对象和原因。
- 完成后刷新数据并保留搜索、筛选、排序和页码；清除失效的勾选状态。

### 5.2 右侧查询区

本节只适用于 `quick-filter-search`。

```text
快速筛选 → 检索框（含批量检索）
```

- 快速筛选用于状态、类型、时间等高频结构化条件。
- 检索框用于名称、ID、描述等关键字字段。
- 批量检索是检索框的内部能力，不是独立按钮，也不是列设置；仅在配置了批量检索字段时展示对应入口。
- 快速筛选和检索框必须能够组合生效。
- 不存在对应能力时不展示控件，不保留空白。
- `condition-search` 不得在右侧重复生成快速筛选或检索框。

### 5.3 页面刷新

- 所有列表页都将刷新入口固定在页面右上角，位置和样式参考安全策略页面，不得放入表格头部查询工具区。
- 复用 `SeerdTableContainer` 的 `reloadButton.portal` 能力，将刷新入口挂载到页面头部右侧；不得重复生成第二个刷新按钮。
- 刷新只重新请求当前页面数据，保留左树范围、概览选择、搜索、筛选、排序和页码。
- 刷新期间保留已有数据并显示加载状态，避免页面闪空和重复触发。

## 6. 搜索与筛选

### 6.1 条件检索模式

- 复用 `SeerdTableContainer` 的 `conditionSearch`，不得自行拼装。
- 作为表格上方独立区域，布局参考安全事件或病毒列表。
- 条件以标签形式展示，支持添加、修改和删除。
- 检索字段及操作符由业务 Reference 和远程配置决定。
- 关键时间可作为默认条件；不可清除时必须始终保留。
- 时间快捷范围和最大跨度使用业务配置，不得写死。
- 清空移除可清除条件；重置恢复业务默认条件。
- 存在检索按钮时，条件编辑后点击检索才提交。
- 执行检索后回到第一页，并保留当前排序。

### 6.2 快速筛选与检索框模式

- 复用 `SeerdTableContainer` 的 `quickSearchFilter`。
- 快速筛选按钮与检索框显示在表格头部右侧，快速筛选在前。
- 业务 Reference 命中 `quick-filter-search` 时，必须同时返回非空的 `quick_filter_fields` 和 `search_fields`；无法为其中一侧提供业务字段时，应重新判断搜索模式，不得生成残缺的双入口模式。
- 快速筛选浮层只放高频筛选字段。
- 筛选确认后生效；重置恢复默认筛选状态。
- 筛选生效时按钮显示激活状态。
- 检索框只搜索配置支持的字段，并提示检索范围。
- 生效条件显示在表格头部下方，支持删除单项和清空全部。
- 删除或清空后，筛选按钮、检索框和列表结果同步更新。
- 条件变化后回到第一页，并保留当前排序。

### 6.3 通用联动

- 搜索、筛选、概览、左树、排序和分页使用同一查询状态。
- 搜索或筛选变化后回到第一页。
- 刷新保留当前搜索、筛选、排序和页码。
- 概览或表格字段产生的筛选必须回显到当前搜索组件。
- 返回列表时恢复搜索、筛选、排序、页码和纵向滚动位置。
- 不得同时维护两份不一致的筛选状态。

## 7. 表格

### 7.1 默认显示列

先确定字段来源和优先级：

1. 用户明确指定列表字段时，以用户定义的字段名称、含义、顺序和默认显示状态为基线。
2. 用户未明确限制“只能使用这些字段”时，可补充业务 Reference 的必要字段和本 Reference 要求的结构列；不得静默补充。
3. 输出方案后必须单独列出 `supplemented_columns`，逐项说明补充字段及原因，并明确告知用户这些字段不是原始需求指定内容。
4. 用户明确要求“不增加字段”或“仅显示指定字段”时，不得补充业务字段；若缺失选择列、操作列等导致指定功能无法成立，应作为冲突项说明，而不是擅自修改。
5. 用户未指定字段时，采用业务 Reference 返回的通用字段基线，再选择能够完成以下判断的最小字段集合。

最小字段集合应支持判断：

1. 当前对象是谁。
2. 是否需要关注或处理。
3. 当前状态或结果是什么。
4. 关键变化发生在什么时间。

同时遵守：

- 操作列始终展示、固定右侧且不可隐藏。
- 有批量操作时，选择列始终展示并固定左侧。
- 至少固定一个主要识别列，保证横向滚动后仍能识别当前行。
- 空间不足时优先隐藏追溯信息、辅助标识和次要判断字段。
- 不得因接口字段较多而默认全部展示。
- 非默认字段可通过列设置恢复，业务禁止展示的字段除外。
- 业务 Reference 声明一组共同表达业务治理关系的字段时，必须作为完整列组输出，不得只复用其中部分字段。例如策略适用范围包含分配对象、排除对象和生效资产时，三列必须共同进入字段结构，除非用户明确要求删减。
- 完整列组不仅需要字段齐全，还必须遵循业务 Reference 定义的顺序并连续排列，不得被其他字段插入或在运行时追加到表格末尾。
- 复用真实参考页面的列时，必须完整复用列契约，包括字段含义、表头名称、表头说明、单元格组件、空值、点击行为、禁用态、固定方式、列宽和响应式表现；只复用单元格组件或相似文案不视为完成复用。

输出字段来源：

```yaml
column_source: user-defined | business-default | mixed
user_defined_columns: 用户明确指定的字段
supplemented_columns: AI 补充的字段及逐项原因
supplement_notice: 输出方案后面向用户的补充说明；没有补充时为空
```

### 7.2 字段展示

- 对象名称或主要标识放在业务字段前部。
- 状态、等级使用项目已有组件和颜色语义。
- 时间使用平台统一格式。
- 无值统一显示 `-`。
- 基础列表的普通数据行默认采用固定单行高度，字段内容长度不得改变行高。
- 普通文本列必须使用平台文本组件或等效的单行省略能力；超长内容显示 `...`，悬浮展示完整内容。
- 仅业务明确规定的主次信息允许双行展示，不得因文本过长自动换行。
- 表头文字禁止换行、截断或省略；不得通过压缩表头换行来减少列表横向宽度。
- 禁止平均分配列宽：
  - 固定内容列使用固定宽度。
  - 短文本列使用最小宽度和内容自适应。
  - 长文本列设置最大宽度并省略。
  - 主要对象列承担剩余弹性空间。
- 每一列的最小宽度必须完整容纳表头全部可见内容，包括表头文字、排序图标、小 i 提示图标、筛选图标以及它们之间的平台标准间距；不得只按表头文字宽度计算。
- 同时存在排序图标和小 i 时，两者必须与完整表头文字在同一行展示，禁止图标换行、遮挡、挤压文字或溢出表头容器。
- 可调整列宽时，用户不得将列缩小到上述表头完整宽度以下；最小宽度必须以最长语言文案和全部表头图标共同计算。
- 双行展示只用于强关联的主次信息，不用于单纯解决文本过长。
- 包含“影响资产”字段时复用 `AssetCard`：点击字段打开资产卡片；该交互不得同时触发行详情。
- 包含“生效资产”字段时复用安全策略的资产标签样式：终端图标 + `X个资产`；全部范围显示“全部资产”。
- 点击生效资产标签打开对应资产明细，不得打开行详情或触发行操作；无数据统一显示 `-`，组件、间距和悬浮效果不得自行仿制。

### 7.3 表头与默认排序

#### 表头说明与宽度契约

- 业务 Reference 声明字段需要解释时，必须复用项目已有表头标题组件输出可见的小 i 和 Tooltip，不得自行拼装图标或只把说明写入字段文档。
- 表头 Tooltip 文案由业务 Reference 提供；本 Reference 只约束位置、触发方式和完整展示。
- 每列必须输出 `header_contract`，至少包含表头文案、是否排序、是否有小 i、Tooltip 文案、是否有筛选图标和能够完整展示这些内容的最小宽度。
- 表头默认态、排序激活态和小 i 悬浮态都必须保持单行且布局稳定，不得因图标出现、隐藏或状态切换改变表头高度。

#### 必须支持排序的字段

表格中存在以下字段时，对应表头必须提供可见、可操作的排序入口：

- 优先级类
- 等级类
- 所有时间类
- 威胁类型

首次排序方向：

- 优先级、等级：业务顺序从高到低。
- 时间：最新在前。
- 威胁类型：按业务字典顺序；未定义时按展示名称升序。

枚举字段必须按业务枚举顺序排序，不得直接按显示文案或字符串值排序。

#### 默认排序

不得根据字段是否存在直接决定默认排序字段。按以下顺序确定：

1. 需求或业务 Reference 已明确：直接采用。
2. 存量页面：保持现有默认排序。
3. 新页面根据核心浏览顺序确定：
   - 日志、安全事件、告警等实时记录按关键发生时间最新在前。
   - 策略、规则等存在生效顺序的数据按业务优先级从高到低。
   - 其他列表复用同类页面；无法判断时列为前置确认项。

业务 Reference 必须返回默认排序字段、业务顺序及接口 `ASC/DESC` 映射。

- 默认只激活一个主排序字段。
- 默认激活列必须显示排序状态。
- 切换排序后回到第一页，并保留搜索和筛选条件。
- 排序不得破坏特殊对象位置等业务不变量。

### 7.4 单行操作

- 行操作按使用频率从高到低排列。
- 外放操作控制在 2 至 3 个；操作较多时保留最高频操作，其余收入更多菜单。
- 危险或不可逆操作优先收入更多菜单。
- 操作列固定右侧，不随横向滚动移动。
- 启停、状态切换等轻量操作可在行内完成。
- 存在复杂表单或关联影响时，不得使用行内直接修改。
- 操作后即时刷新状态并提供成功或失败反馈。
- 字段操作和操作列点击不得触发行主交互。
- 行操作因对象类型、权限或业务状态不可执行时必须禁用，并通过悬浮展示该操作对应的具体原因；不得只依赖文字颜色表达禁用状态。

### 7.5 列设置与滚动

- 支持显示/隐藏、顺序和宽度调整，并按账号保存。
- 列设置属于表格布局能力，入口位置复用对应真实页面；不得放入快速筛选与检索框组合，也不得将批量检索入口误识别为列设置。
- 同时存在本地列定义、远程列配置或 Mock、用户已保存列布局时，必须保证字段标识、默认显隐和默认顺序一致。
- 新增字段不得只加入本地 `columns`；必须同步检查远程列配置，否则字段可能在运行时被追加到末尾。
- 最终列顺序必须按以下链路验证：本地列定义 → 远程列配置或 Mock → 用户已保存布局 → 浏览器运行态。
- 业务规定为固定顺序的完整列组属于布局不变量；历史列配置与其冲突时，应迁移或修正旧配置。
- 操作列和选择列不可通过列设置隐藏。
- 横向滚动条出现时应保持可见。
- 纵向滚动时表头保持可见。
- 1366 和 1920 宽度下，核心判断字段应默认可见。
- 除日志等字段较多场景外，默认列应尽量避免横向滚动。
- 不得为消除滚动而过度压缩列宽，导致大面积省略。

## 8. 分页与选中信息

- 分页放在表格底部，展示总数、当前页和每页数量。
- 页码、每页数量和总数必须与当前查询一致。
- 搜索、筛选、左树或排序变化后回到第一页。
- 手动刷新保留当前页；当前页无数据时回到最后有效页。
- 有批量选择时展示选中数量和清空入口，效果参考客户端列表。
- 跨页选择、全选范围和清空规则必须由业务明确。

## 9. 页面状态

必须覆盖：

- 首次加载。
- 刷新加载。
- 初始无数据。
- 搜索或筛选无结果。
- 请求失败。
- 部分区域失败。
- 无权限或业务受限。

约束：

- 初始无数据可以提供新增等业务引导。
- 搜索无结果只提供调整条件或重置入口。
- 刷新时保留已有数据，避免整个页面闪空。
- 概览、左树或表格局部失败不得阻塞其他区域。
- 空状态和异常状态不得改变页面固定结构。

## 10. 实现与证据

证据优先级：

1. 用户指定的真实页面和当前项目实现。
2. 同产品、同类型页面。
3. 平台业务组件。
4. iDux 组件规则。
5. 本 Reference。

冲突时遵循：

```text
用户明确要求 > 业务不变量 > 真实产品基线 > 本 Reference
```

实现约束：

- 标准列表优先复用 `SeerdTableContainer`。
- 搜索、筛选、排序、分页和列设置使用现有容器能力。
- 不得只实现静态视觉；所有入口必须具备真实状态和反馈。
- 不得修改业务 Reference 定义的字段含义、默认排序和特殊对象约束。
- 找不到真实组件或代码证据时，不得虚构交互入口。
- 文本截断和列顺序必须在浏览器运行态验证，不得只检查本地列数组或静态代码。
- 使用超长中文、英文和无空格连续字符验证普通文本列；所有有效数据行高度必须一致。
- 检查浏览器最终表头顺序，确认完整业务列组字段齐全、连续且顺序正确。

## 11. 输入与输出

仅在业务 Reference 返回 `list`、`search`、`filter` 或 `sort` 能力时读取。

输入：

- `business_invariants`
- `page_inventory`
- `design_capabilities`
- `asset_applicability_check`
- `reference_evidence`
- `acceptance_checks`

输出到 `visual_contracts`：

```yaml
list_type: basic-list | overview-list | tree-list | tree-overview-list
business_type: business-browse | config-manage | operation-closed
search_mode: condition-search | quick-filter-search
page_structure: 页面区域和层级
overview_contract: 概览指标、筛选和展开收起规则
tree_contract: 范围、默认节点和切换行为
toolbar_contract: 操作、状态、勾选限制和反馈
asset_applicability_check: 条件性资产适用检测按钮、参考交互和数据映射
refresh_contract: 页面右上角刷新入口及状态保留规则
search_fields: 普通检索、批量检索字段及操作符
quick_filter_fields: 快速筛选字段
default_conditions: 默认且不可丢失的条件
column_contract: 默认列、顺序、宽度、固定和隐藏规则
header_contract: 各列表头文案、排序、小 i、筛选图标、Tooltip、禁止换行及最小完整宽度
disabled_state_contract: 表头按钮、行操作、状态开关、菜单项和选择框的禁用条件与 disabled_reason
column_source: user-defined | business-default | mixed
user_defined_columns: 用户明确指定的字段
supplemented_columns: AI 补充字段及原因
supplement_notice: 面向用户的补充说明；没有补充时为空
sort_contract: 可排序字段、默认排序、首次方向及接口映射
pagination_contract: 分页、选中和刷新规则
state_contract: 加载、空、异常和权限状态
reference_evidence: 页面、代码和组件证据
```

## 12. 准出自检

- 已明确 `list_type`、`business_type` 和 `search_mode`。
- 未生成缺少业务依据的概览区或左树。
- 概览展开收起按钮与病毒列表保持一致，收起不影响当前查询状态。
- 高级检索没有被错误实现为右侧快速筛选。
- 快速筛选模式同时具备快速筛选按钮和检索框。
- 批量检索位于检索框内部，没有被误识别为列设置。
- 刷新入口位于页面右上角，并且页面内只有一个刷新入口。
- 搜索、筛选、概览、左树、排序和分页使用同一查询状态。
- 新增使用主按钮样式。
- 支持非全部资产生效时，左侧存在正确命名且不依赖勾选的资产适用检测按钮；固定全局生效时不存在。
- 外放对象操作使用动作名称，没有出现「批量删除」「批量启用」「批量禁用」。
- 依赖勾选的操作未勾选时禁用，并具有指定提示。
- 所有禁用的按钮、行操作、状态开关、菜单项和选择框均有与当前操作对应且可真实悬浮触发的原因。
- 已处理勾选上限、不支持对象和批量操作失败反馈。
- 已选数量和清空入口参考客户端列表。
- 默认显示列足以完成识别、判断、状态确认和时间判断。
- 用户指定字段已优先采用；任何自动补充字段均已通过 `supplemented_columns` 列出，并在方案后明确告知用户。
- 用户明确限制只使用指定字段时，没有擅自补充业务字段。
- 业务 Reference 声明的完整列组没有被部分复用；参考列的表头、单元格、空值、交互、禁用态和宽度契约均已覆盖。
- 普通文本超长时保持单行省略，所有有效数据行高度一致。
- 已使用超长中文、英文和无空格连续字符验证单行截断。
- 本地列定义与远程列配置的字段、顺序和默认显隐一致。
- 完整业务列组在最终运行态中连续且顺序正确。
- 已检查浏览器最终表头顺序，而非仅检查本地 `columns` 数组。
- 操作列始终展示、固定右侧且不可隐藏。
- 所有表头保持单行完整展示，没有换行、截断或省略；列最小宽度足以同时容纳完整表头文字、排序图标、小 i、筛选图标和标准间距。
- “影响资产”使用 `AssetCard`，且不会误触发行详情。
- “生效资产”复用安全策略资产标签，点击只打开对应资产明细。
- 列表顶部提示条与对象白名单的位置、边界、高度和内容对齐一致。
- 优先级、等级、所有时间和威胁类型均有排序入口。
- 默认排序来自业务浏览顺序，没有按字段存在情况直接猜测。
- 已覆盖加载、空、无结果、失败和业务受限状态。
- 所有页面结构、组件和交互均有真实证据。
- 未破坏任何 `business_invariants`。

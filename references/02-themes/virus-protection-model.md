## 调用契约

## 约束条件
- 当用户需求只涉及病毒查杀局部区域时，也必须保留本 Reference 中定义的病毒记录关系、处置动作约束、处置记录文案和跨模块跳转关系。
- 未定义的业务枚举、权限、接口状态或异常文案不得编造成确定规则，应与调用方进行确认
- 除调用方明确给出的业务专属规则外，完整执行本文档原有规则；不得删除、弱化或自行改写原有规则。
- 页面通用模板冲突时，优先级为：用户明确要求 > 本 Reference 业务专属规则 > 页面通用模板 > 组件库默认行为。


## 模块定位与用户目标
- `病毒列表`模块主要承载终端侧的病毒检出记录。
- 主要服务企业安全运营人员在这里完成病毒研判、处置确认和结果追踪。
- 此处一条病毒加一台资产生成一条病毒数据，不做攻击链的聚合，也不做跨资产合并。
- 病毒在端侧进行处置后不会重新上报处置记录，所以数据记录维持在检出阶段


## 病毒模型变更处理
当收到病毒相关需求时，AI 要优先判断是否命中已有威胁类型

- 当需求命中已有威胁类型时：无需对概览区和筛选区做变动
- 当需求新增了一种新的`威胁类型`时，
    1. 需要在筛选区的 value 值中新增此类型
    2. 判断是否可以归类到现有的`检测场景`中，若不可以，则需要在筛选区的 value 值中新增此类型，并在顶部概览区的`检测场景`中新增一个卡片



## 病毒列表 DEMO 数据生成规则

AI 生成 DEMO 数据时，只保留与本次需求相关的示例，其他不展示。

1. 先判断本次需求相较于现有环境中的变化点。
2. 只围绕变化点生成示例，数量以“足够表达设计差异”为准，不追求多。
    - 只生成能说明本次变化的样例。
    - 每条 DEMO 数据必须对应至少一个明确的设计目的。
    - 若本次需求只影响局部字段或单一操作，示例数据也应保持最小集合。
    - 若变化点本身分为多个互不相同的攻击场景，则每个场景至少保留 1 条示例数据。

### 1.2 病毒命名规则

- 若需求中未输入命名规则，全部使用标准四段式命名，如：`Backdoor.Win64.CobaltStrike.beacon`
- 标准四段式命名的病毒才支持“情报查询“
- 以下场景不采用四段式命名：

| 场景              | 命名规则                                                    | 示例                                            |
| --------------- | ------------------------------------------------------- | --------------------------------------------- |
| IOC规则定义的病毒      | 使用 IOC 规则定义时设置的告警命名                                     | `IOC_Malware_UR20260717003`                     |
| 勒索防护类          | {威胁类型}.{攻击进程所在操作系统类型，获取不到则取 Unknown}.{家族名 或 行为子类} | `Ransom.Win32.LockBit / Ransom.Win32.FileCoder` |
| 外联拦截            | {威胁类型}.{操作系统类型}.{家族名}.IPO_{IP后两位}P{端口}        | `hacktool.Win32.gooxion.IPO_63P80`              |




### 1.3 病毒相关路径显示规则
- `病毒相关路径`显示的是攻击者方的病毒文件或进程路径，如：`C:\Users\Public\system32\cleanmgr.exe` 
- 若需求中未输入明确规则，均展示病毒的所处路径
- 以下场景为特殊展示：

| 场景           | 显示规则                          | 示例                                                                       |
| ------------ | ----------------------------- | ------------------------------------------------------------------------ |
| 外联拦截         | {设备上发起外联的进程路径} → {外联IP地址:端口} | `C:\Program Files\Google\Chrome\Application\chrome.exe → 112.213.116.3:80` |
| 远端设备加密本机共享文件 | 远端设备 {攻击方设备IP} 上的勒索病毒        | `远端设备 100.100.1.33 上的勒索病毒`                                 |



### 1.4 处置操作规则矩阵


#### 1.4.1 支持的处置动作定义

- 触发`添加白名单`后，路由到 [AES 规则业务模型](rule-management-model.md)
- 触发其他处置操作后，路由到 [任务中心页面模型](task-center-model.md)

| 动作     | 含义                                                 |
| ------ | -------------------------------------------------- |
| 隔离文件   | 结束进程+隔离文件（将文件放入隔离区）。 |
| 结束进程   | 无驻留项病毒：kill 目标进程； 有驻留项病毒：kill 目标进程并+清理驻留项。         |
| 清理驻留项  | 清理计划任务、注册表启动项、服务等驻留项。                              |
| 恢复文件   | 把文件从隔离区释放出来。                                       |
| 解除勒索遏制 | 系统发现勒索加密后会进行自动遏制，这里支持解除遏制，具体包括：解除进程写入文件、解除进程启动的限制 |
| 添加白名单  | 文件hash、路径、文件夹、域名、IP地址加入到白名单，后续跳过扫描，不再触发告警          |



#### 1.4.2 不同病毒类型提供的手动处置操作


| 病毒类型 / 场景 | 可用操作                                                                 |
| --------- | -------------------------------------------------------------------- |
| 文件类      | 1）`隔离文件`； 2）文件隔离后支持`恢复文件`； 3）`添加白名单`（支持文件 hash）。                       |
| C2 远控类    | 仅支持自动处置（处置动作为拦截外联），列表不提供处置入口。支持`添加白名单`
| 内存检测类   | 1）若进程可 kill，支持`结束进程`； 2）若能检出注入进程的恶意文件，支持`隔离文件`； 3）若能检出驻留项，支持`清理驻留项`。 |
| 勒索防护类   | 1）若已隔离病毒进程文件，则支持`恢复文件`；2）若未能隔离病毒进程文件，则支持`解除勒索遏制`和`隔离文件`）   |

补充规则：
- C2 远控类：默认由系统自动拦截外联，列表不提供普通处置入口，但可支持`添加白名单`。
- 勒索防护类：当发现勒索加密行为，系统会自动遏制（遏制动作包括：限制进程写入文件、限制进程启动）。列表不提供遏制入口。系统遏制后会进一步处置，处置动作包括`结束进程`和`隔离文件`，若处置失败，则此处支持`隔离文件`


### 1.5 处置描述

- 优先使用已有的处置动作
- 显示多个处置动作时，中间用；分割
- 优先展示最终处置结果，而不是完整动作流水。
- 多个处置动作均成功时，只展示处置强度最高、最能代表当前安全状态的动作。
- 成功的中间动作、辅助动作、前置遏制动作默认不展示。
- 如果最终动作失败，则展示失败动作，并保留已成功的关键遏制动作。
- 如果存在未完成、失败、部分成功、需人工介入的事项，必须展示。
- 提供下方的示例数据为参考：

1）普通的病毒样本检出：
| 场景描述 | 回显举例 |
| ------  |----------------------------- | 
| 隔离了病毒文件 | 已隔离文件 |   
| 隔离文件后又恢复了文件 | 已恢复文件  |


2）有驻留项的病毒，结束了进程并且清理了驻留项：
| 场景描述 | 回显举例 |
| ------  |----------------------------- | 
|需要重启后才能彻底清除驻留项| 已结束进程；已清理驻留项 3/4；待重启设备 |   
|不需要重启| 已结束进程；已清理驻留项 3/4 |   


3）本机进程加密本机文件或网络共享文件，系统进行的处置流程是：限制文件写入→结束进程→隔离文件：
| 场景描述 | 回显举例 |
| ------  |----------------------------- | 
| 如果只有第一步成功了 | 已限制文件写入；结束进程失败；已还原文件 80/86 个 |
| 如果前两步成功了，隔离文件失败了| 已限制进程启动；隔离文件失败；已还原文件 80/86 个 |
| 如果三步都成功了| 已隔离文件；已还原文件 80/86 个 |

## 2. 病毒详情 Drawer


### 2.1 标题区
#### 2.1.1 标题
- 标题命名规则：{威胁等级} {威胁类型} ｜ {病毒名称}

#### 2.1.1 操作
- 详情 Drawer 承接列表中的处置操作。
- 所有标准四段式命名的病毒都支持`情报查询↗`
- 若支持的处置动作 ≥ 2 个，则操作收纳在`处置（下拉选择）`中，旁边显示`情报查询↗`
- 若支持的处置动作 = 1 个，则直接平铺该操作，例如`隔离文件`、`情报查询↗`。
- 若处置操作后有对应的流转模块，则需要放在`处置（下拉选择）`中。比如：文件已隔离，需要显示`文件隔离区↗`，点击后新页签跳转到对应页面。
- `处置（下拉选择）`下拉后的处置操作和跳转操作之间有分割线，跳转操作放最下面
- 只显示支持的处置，不支持的不显示


### 2.2 摘要区

- 摘要区字段的 value 值显示承接自列表，应当保持一致。
- 摘要区支持省略展示的只有`标记备注`，其余都应完整展示
- 当涉及失败项时，数字标红，比如：`已清理驻留项 3/4`，这里的`3/4`标红



### 2.3 病毒进程信息 / 病毒文件信息 / 远端攻击来源信息
- 区块标题必须随检测场景变化，不要固定为`病毒文件信息`
- 字段无值时显示 `-`，不得显示空白、null 或 undefined。
- 不同检测场景下，显示的区块标题和内容不同，显示规则如下：

| 检测场景          | 区块标题           | 显示字段           | 说明         |
| --------------------- | ---------------- | ------------------------- | -----|
| 基于病毒文件检出     | 病毒文件信息   | 文件名、文件路径、文件hash、文件大小、文件格式、文件签名、文件创建时间。  | 无签名时value显示`无签名`，字色 #C2862D                                                                                                |
| 基于压缩包文件检出  | 病毒文件信息   | 文件名、文件路径、文件hash、文件大小、文件格式、文件签名、关联压缩包、关联压缩包hash、关联压缩包来源、关联压缩包创建时间。 | 1）“文件路径”中，压缩包释放的文件用">>"表达。举例：`C:\Users\Ryan\Desktop\test.7z >> 10.11人员名单.exe` <br> 2）释放的文件信息和压缩包信息之间用分割线隔开 |
| C2 远控类   | 病毒进程信息   | 进程名、PID、进程文件路径、关联文件hash、命令行参数、C2外联行为、威胁入口。     |       |
| 基于内存检出的病毒  | 病毒进程信息   | 进程名、PID、进程文件路径、关联文件hash、命令行参数、威胁入口。                               |      |
| 远端来源加密本机共享文件     | 远端攻击来源信息 | 远端IP、远端访问账号、访问共享路径。 |   |


### 2.4 资产信息

- 若无特殊说明，不要更改`资产信息`模块的任何内容。
- 资产信息属于病毒记录上下文，不应被病毒文件、进程或处置字段替代。
- 如果需求涉及资产字段调整，应确认是否属于通用资产信息组件规则；若属于通用组件，应交由对应页面通用模板或资产模型处理。



### 2.5 最近病毒检测信息

- 显示字段：若无特殊说明，不要更改`最近病毒检测信息`模块的字段，但其 value 值应与列表保持一致
- 若是非平台下发的任务，`平台扫描任务 ID`的 value 值显示 `-`；若平台下发的任务则显示具体的任务ID，点击可跳转对应任务的任务详情页。


### 2.6 处置记录

- 一个处置记录可以包含多个处置描述片段，但每个片段必须能对应真实处置动作
- 此处不记录客户端侧手动处置动作
- 显示格式为：`[{处置方式}] {处置详细描述}`。
- 处置成功的 `[{处置方式}]` 使用绿色 `#12A679`；处置失败的 `[{处置方式}]` 使用红色 `#CF171D`。
- 所有实体（进程、文件、路径、IP 等）都应使用标签样式展示。
- 若处置方式是`管理员处置`，且处置失败，则在失败原因后面应显示：`前往任务“{任务名称}”查看详情`，点击可跳转对应任务的任务详情页。
- 提供下方示例数据作为参考：
```text
[管理员处置] 已隔离文件，文件名为 SohuNews.exe
[自动处置] 隔离文件失败，文件名为 SogouExe.exe，失败原因：文件处置权限不足，无法处置（错误码：0x10010008）
[自动处置] 已删除启动注册表项 AdobeUpdate。注册表路径：HKCU\Software\Microsoft\Windows\CurrentVersion\Run
键值数据："C:\Users\Public\update\AdobeUpdate.exe" -silent
```


### 2.7 GPT 分析



#### 2.7.1 触发规则

- 严重和高危病毒：打开详情 Drawer 后自动触发告警解析。
- 中危和低危病毒：需要用户点击`生成 GPT 分析`后才显示解读信息。
- 解读信息首次生成时需要携带打字机效果。
- 同一记录二次打开时，如果 GPT 已解析过，不再要求用户点击按钮，直接显示即可。
- GPT 分析不得替代处置状态和处置记录的业务真值。
- 有CG图的就有`时间线分析解读`，否则没有。



#### 2.7.2 生成的 GPT 分析类型


| 类型      | 内容结构   | 操作入口             |
| ------- | -------------------------------------- | --------------------------- |
| 简要解读    | 1）只有一段对病毒的解析+处置情况的文本。<br> 2）文本中实体（如进程名、IP、文件名、文件路径等）使用标签样式    | 底部有`重新生成分析`按钮； 没有`攻击链分析`按钮。 |
| 时间线分析解读 | 1）包含整体文本解读（病毒的解析+处置情况）、时间线分析构成 <br> 2）其中`时间线分析`的构成可见 [时间线分析解读](#273-时间线分析解读)  | 底部有`重新生成分析`按钮； 有`攻击链分析`按钮。  |



#### 2.7.3 时间线分析解读

- 时间线分析只描述攻击过程、风险证据和异常点，不描述平台处置动作或处置结果
- 攻击主要描述应优先解释关键风险和证据，避免泛泛而谈。
- 异常点说明必须采用 `{异常点}：{详细解释这个异常为什么异常}` 的结构。
- 下方为时间线分析的具体构成：

| 构成主体   | 说明 / 规则           | 示例  |
| ------ | ---------------------------------------------- | ------------------ |
| 攻击阶段   | 攻击链里面的一个大步骤                                    | 恶意文档投递与诱导执行                                                         |
| 攻击时间点  | 攻击节点发生的时间                                      | 2025-12-12 19:12:12                                                 |
| 攻击主要描述 | 说明发生了什么 描述长度和展开方式遵循 GPT 分析组件能力；正文应优先解释关键风险和证据。 | 文件名“2023税-务-总-局-通-知.doc.exe”伪装为DOC文档，但实际为可执行程序，利用了对官方通知的信任进行社会工程学攻击 |
| 异常点说明  | {异常点}：{详细解释这个异常为什么异常}                      | 文件类型异常：文件名伪装为 DOC 文档，但实际为可执行程序。                                     |



## 输出自检清单

AI 生成方案后必须逐项核对：   
- [ ] 病毒列表页、病毒详情 Drawer、处置记录、GPT 分析的规则没有互相覆盖。  
- [ ] 所有业务专属字段均按本 Reference 定义展示，通用列表 / 表单 / Drawer 能力交给页面通用模板。  
- [ ] 不同检测场景下的病毒相关路径、实体信息区块和处置描述均匹配对应规则。
- [ ] 跳转到任务详情、文件隔离区、情报查询时使用新页签。

## 调用契约

- 接收入口 [`SKILL.md`](../../SKILL.md)、[病毒防护](virus-protection-model.md) 提供的结构化上下文包，不重新判断是否应归入任务中心。
- 涉及任务表单时，先由 [AES 表单模板](../03-templates/form.md) 确定容器和页面结构，再由 [AES 表单管理 Pattern](../04-patterns/form-management.md) 处理字段组织与交互；执行对象选择按需调用 Feature。本 Reference 只定义任务业务模型。
- 涉及列表时，先由 [AES 列表模板](../03-templates/list.md) 确定页面骨架，再由 [AES 表格管理 Pattern](../04-patterns/table-management.md) 处理搜索、筛选、排序、列配置和批量操作。



## 模块定位与用户目标

- 任务中心不是策略中心
- 任务中心承载管理员手动下发到客户端的所有任务，主要在此处追踪每台资产的执行结果
- 威胁处置类任务不支持在任务中心提供创建入口，但要在`任务记录`页面追踪执行结果



## 核心对象介绍
| 页面中的命名 | 说明 |
| -- | -- |
| 任务类型 | 任务类型分为大类和小类，大类是指概览区`任务类型`中的统计卡片；小类是指表格中`任务类型`这个字段的赋值。|
| 任务记录 | 任务记录用于承载已经生成并开始执行的任务实例，描述已经发生的一次任务实际执行的过程和结果。|
| 任务计划 | 任务计划用于承载未来将要执行的任务安排，包括预约执行的任务和周期任务。|
| 预约任务 | 预约任务是指定一个未来执行时间的任务，只执行一次。比如：2022-12-12 00:00执行 |
| 周期任务 | 周期任务指会循环进行的任务策略，比如：每周一的凌晨2:00进行扫描。|
| 任务状态 | 每个任务里面包含多个不同资产的执行结果，这里以任务为维度显示状态，主要标记任务是否执行完毕。|
| 执行结果 | 每台资产都有唯一的执行结果，由资产上报上来。包括：`未开始`、`执行中`、`成功`、`失败`、`已终止`|



## 任务生成关系
| 任务执行时间 | 是否流入`任务计划` | 是否流入`任务记录` | 说明 |
| -- | -- | -- | -- |
| 立即执行的任务 | 否 | 是 | 创建后直接生成任务记录并开始执行 |
| 预约任务 | 是 | 到执行时间后自动生成 | 执行前在任务计划中展示，到达执行时间自动生成一条任务记录 |
| 周期任务 | 是 | 每到设定的执行时间生成一条记录 | 任务计划持续存在，每次到执行时间生成一条任务记录 |



## 变更规则

### 需求需要新增或调整已有任务类型时

-  判断它最适合落在哪个已有任务大类里：
  - 如果只是新增同类任务：
    - 更新任务类型映射关系
    - 若支持新增，更新创建任务的抽屉
    - 参考同一个大类下的其他任务生成任务详情

  - 如果是新的任务大类：
    - 在概览区的`任务类型`中新增一个卡片
    - 创建任务类型映射关系
    - 若支持新增，更新创建任务的抽屉
    - 按 [任务详情页](#3-任务详情页面) 规则生成任务详情



### 需求对已有的设计进行更改时：

更改后，若涉及关联面，则关联面也要同步更改
- 关联面包括：
    - 是否增加、删减、修改表格列字段
    - 是否增加、删减、修改快速检索字段
    - 是否增加、删减、修改概览区的统计数据
- 若概览区修改，必然会对检索区进行同步修改
- 举例：在创建任务时新增了一个字段，那么在对应的表格中也要同步增加该列，且检索区也要同步增加该检索条件



## 任务中心的 DEMO 数据生成规则

- AI 生成 DEMO 数据时，只保留与本次需求相关的示例，其他不展示。
  1. 先判断本次需求相较于现有环境中的变化点。
  2. 只围绕变化点生成示例，数量以“足够表达设计差异”为准，不追求多。
    - 只生成能说明本次变化的样例。
    - 每条 DEMO 数据必须对应至少一个明确的设计目的。
    - 若本次需求只影响局部字段或单一操作，示例数据也应保持最小集合。

- 在输出 Demo 时，必须预置一些已经下发过的历史任务数据，且这些任务数据必须是本次需求相关的。
  - 历史任务必须形成完整链路：任务记录、任务详情里面的的 TaskID 一致。
  - 不得生成无关任务来填充页面



## 1. 任务记录页

### 1.1 表格核心字段信息说明
| 字段名称 | 说明 |
| -- | -- |
| 任务名称 | 默认任务名称取值规则{任务小类}_{时间戳}。比如：`结束进程_20260721170115` |
| 任务类型 | 表格中的任务类型均展示小类 |
| 任务状态 | 见 [1.2任务状态界定规则](#12-任务状态) |
| 任务执行结果 | 统计该任务下每个执行结果的数量；隐藏统计数值为 0 的状态 |
| 操作 | 见 [1.3 支持的操作及操作说明](#13-支持的操作及操作说明) |

### 1.2 任务状态界定规则
| 任务状态 | 界定规则 |
| -- | -- |
| 执行中 | 任务内存在至少 1 个资产执行结果为`未开始`或`执行中`。 |
| 执行完成：全部成功 | 任务内不存在`未开始`或`执行中`或`失败`的资产，且所有资产执行结果均为`成功`或`已终止`。 |
| 执行完成：全部失败 | 任务内所有资产执行结果均为`失败` |
| 执行完成：部分失败 | 任务内不存在`未开始`或`执行中`的资产，且同时存在`失败`和`成功 / 已终止`的资产。 |

### 1.3 支持的操作及操作说明

#### 1.3.1 操作项解释
任务详情：点击下钻进入到`任务详情`页面，查看资产级执行明细
终止扫描：针对`未开始`的资产取消扫描任务，针对`执行中`的资产下发一个`终止扫描`任务，其他状态不予理会
停止下发：针对`未开始`的资产取消任务，其他状态不予理会
再次下发：再次下发会基于原任务生成一个新任务。新任务默认继承原任务的全部信息，但以下字段固定调整：
  - 执行计划：固定改为`单次执行`、`立即开始扫描 ~ 直至扫描结束`
  - 任务名称：默认回填为`{原任务名称}_副本` 
  - 任务对象：默认回填为所有执行结果为`失败`的资产


#### 1.3.2 不同任务类型支持的操作说明
- 若是属于已有的任务大类，则完全参考该大类下其他任务的操作项来实现
- `终止扫描`任务是一个特例，不要将其作为参考
- 若是新的任务大类，则支持的操作包含：
  - 一定有`任务详情`
  - 任务状态为执行中时则显示：`停止下发`
  - 任务状态为`执行完成：全部失败`或`执行完成：部分失败`时则显示：`再次下发`；
  - 任务状态为`执行完成：全部成功`是，显示禁用态的`再次下发`，悬停后tooltips提示：`已完成任务，无需重复执行`

## 4. 创建任务
如果需求不涉及新的任务类型，则跳过此模块；如果需要创建任务，则阅读以下部分：

1. 判断是否可以在`任务中心`创建该任务。若需求中无特殊说明，则 AI 判断，判断依据：
  - 不支持：所有`威胁处置`类任务不支持在任务中心提供创建入口
  - 不支持：依赖上下文才能进行任务下发的，不支持创建入口
  - 支持：只选择资产或资产组是否就能合理执行的任务，比如：客户端运维、病毒扫描

2. 确认创建任务的容器形态：
  - 若是在`任务中心`页面创建，则采用 drawer
  - 若是在其他模块作为创建入口（比如在`客户端管理`里面下发病毒扫描任务），则采用 modal
  - 从任务中心统一“新建”入口进入时，先选择任务类型，再进入对应的完整任务配置，向表单模板返回 `flow_structure: progressive`；两层内容轮换展示，不形成浮层叠加
  - 已明确具体任务类型的直接创建、编辑或重新下发，不再经过类型选择层；其流程结构继续由表单模板根据实际任务判断
  - 容器由 [AES 表单模板](../03-templates/form.md) 确定，容器内字段方案由 [AES 表单管理 Pattern](../04-patterns/form-management.md) 完成

3. 判断是否有必要支持预约执行。若需求中无特殊说明，则 AI 判断，判断依据：
  - 不支持：正在活跃的威胁，需要快速处置，如：结束进程、隔离文件
  - 不支持：可用性状态变更，如：启用客户端、禁用客户端
  - 支持：任务对执行时间要求严苛，需要避开业务高峰期，降低业务影响。

4. 判断是否有必要配置为周期执行的任务。若需求中无特殊说明，则 AI 判断，判断依据：
  - 不支持：不支持预约执行任务的一定不支持周期任务
  - 不支持：执行的对象是一次性威胁，执行后就没有再执行的必要，如：隔离资产、隔离文件
  - 支持：任务具有重复执行的价值，如：病毒扫描

5. 创建任务表单的分组逻辑如下：

  5.1 表单分组逻辑
  | 分组名称 | 分组规则 | 判断标准 | 组内必含配置项 |
  | -- | -- | -- | -- |
  | 任务信息 | 与任务展示、沟通、审计说明相关，但不直接决定执行对象的字段 | 去掉这些字段后，任务仍然知道“要对什么对象执行什么动作”，只是缺少名称、说明或提示 | 任务名称、任务备注 |
  | 任务对象 | 放置任务真正要作用的对象主体，以及识别这些对象所必需的信息。 | 去掉这些字段后，任务无法确定“对谁/对什么执行动作”。 | 资产范围 |
  | 执行计划 | 预约任务和周期任务需要显示此分组，否则隐藏此组。放“这条任务什么时候执行”的信息 | 与任务执行时间相关的配置 | 预约时间 |
  | 高级设置 | 放低频、兜底、异常处理类配置，不影响任务主流程的理解，只影响任务在边界情况下怎么执行。 | 去掉这些字段后，任务的主体动作和执行计划仍成立，只是少了边界行为控制 | 任务有效期 |

  5.2 参考页面
  | 页面位置 | 即刻下发的任务 | 预约任务 | 周期任务 |
  | -- | -- | -- | -- |
  | 任务中心 | 任务中心/新增/启用客户端 | 暂无 | 任务中心/新增/快速扫描 |
  | 非任务中心 | 病毒防护/处置/隔离文件 | 暂无 | 暂无 |

### 5.3 备注默认值与重新下发

- 从任务中心自身常规新增任务时，`任务备注`默认为空。
- 从其他业务模块基于当前对象快速新增任务时，调用 [`contextual-remark-default`](../05-features/contextual-remark-default.md) Feature，仅处理任务的 `任务备注` 字段。
- 来源模块名称使用实际页面展示名称，来源对象名称使用来源页面展示的具体对象名称；缺少对象名称时备注保持为空，不得自行生成替代名称。
- 默认备注格式为：`通过{模块名称}【{具体对象名称}】添加`。
- 默认备注仅在新增表单初始化时回填一次；用户修改或清空后不得再次自动覆盖。
- 任务重新下发基于原任务生成新任务，备注沿用原任务已保存的备注，不重新生成来源备注。

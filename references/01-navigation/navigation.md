# AES 导航、功能入口与变更影响检查

> **归属：AES Product Design。** 本 Reference 是 AES（深信服下一代端点安全）产线专属设计规范，专门约束 AES 导航与功能入口，不作为 Common Design 通用导航规范。
> `Coverage: extend`

本文定义 AES 导航格式、功能入口判断和变更影响检查方法。当前菜单分类、菜单名称、路由和菜单 Key 会随产品版本变化，必须以调用时获取的最新资料为准；本文不维护永久固定的菜单树或业务关系库。

## 1. 定位与调用时机

当需求涉及新增功能、模块改造、菜单归属、页面入口或跨模块跳转时，由 `prd-design-code` 在主题层之前调用本文。

```text
需求分析 → Navigation → Theme → Template → Pattern → Feature → Component → Copy
```

本文只确定“从哪里进入”和“哪些入口需要检查”，不定义业务对象、生命周期、页面结构或模块间完整业务关系。

## 2. 导航现状动态读取

按以下优先级确认当前导航：

1. 用户本次明确指定的菜单或入口；
2. 当前项目代码中的路由和菜单配置；
3. 当前版本截图、原型或产品资料；
4. AES Product Design 中已有导航参考；
5. Common Design 的通用入口判断规则。

菜单名称、分类和层级只作为当前任务输入，不写成永久规则。资料不一致时，用户要求优先；无法确认当前版本时，输出候选路径并进入待确认，不根据功能名称自行创建菜单。

## 3. AES 导航格式

### 3.1 左侧导航

AES 使用左侧导航承载一级和二级导航，不使用 L 型导航。

```text
左侧导航
├── 一级导航
│   ├── 二级导航
│   └── 二级导航
└── 一级导航
    └── 二级导航
```

- 左侧导航展示一级、二级导航，不展示三级菜单；
- 一级导航区分相对独立的产品能力域；
- 二级导航承载一级导航下的稳定业务模块；
- 没有二级子项的一级导航可以直接作为页面入口；
- 当前项保持展开和高亮；
- Common Design 的 `l-shaped` 导航不适用于 AES。

### 3.2 路由级 Tab

三级内容使用所属二级导航页面的路由级 承载：

```text
┌──────────────────┬──────────────────────────────────────────────┐
│ 左侧导航           │ 账户权限   │ 账号管理      │ 角色管理          │
│                    │            │（当前 Tab）   │                  │
│ 配置管理           ├────────────┴───────────────┴──────────────────┤
│ └─ 账户权限        │                  当前 Tab 页面内容             │
│                    │                                                │
└──────────────────┴──────────────────────────────────────────────┘
```


路由级Tab 必须归属于明确的二级导航。Tab 切换的刷新、筛选和状态保留规则由后续页面和交互层补充。详情页内部 Tab 属于内容组织层级，与路由级 Tab 不混用。

### 3.3 页面内入口

工具栏按钮、行操作、详情区操作、弹窗、抽屉和轻量配置均属于页面内入口，不属于菜单层级。此类入口必须写明所属主页面、触发操作和打开容器。

## 4. 一级导航归属参考

以下大类只用于用户未指定入口时的推荐判断，不是固定菜单清单。最终路径必须结合当前导航现状确认。

| 一级导航参考 | 推荐放置的需求类型 | 归属说明 |
| --- | --- | --- |
| 首页 | 全局态势、整体价值、待关注事项、跨模块监控和快捷入口 | 不预设具体内容，由用户需求和当前首页设计决定 |
| 威胁检测 | 威胁发现、告警分析、安全事件、病毒检测、日志调查和攻击分析 | 主要任务是发现、研判和溯源威胁 |
| 任务与处置 | 扫描、查杀、隔离、修复、下发处置、运维任务和结果跟踪 | 主要任务是执行动作并查看结果 |
| 策略与规则 | 安全策略、检测策略、IOC、黑白名单、规则条件、优先级和生效配置 | 默认承载策略、规则和防护配置 |
| 客户端管理 | 客户端资产、终端部署、升级、客户端状态和资产生命周期 | 主要任务是管理终端对象 |
| 端点防火墙 | 防火墙规则、防火墙策略和端点网络访问控制 | 业务上可归入策略与规则；为突出独立网络防护价值时可单独设置入口 |
| 配置管理 | 账户权限、消息通知、授权、身份同步、连接器、系统日志和平台基础配置 | 仅承载平台级基础配置 |

首页不预设推荐需求类型。其他模块发生变化时，只检查首页是否实际使用了相关统计、状态、待办或快捷入口。

## 5. 入口选择规则

按以下顺序判断：

1. 复用已有一级或二级导航；
2. 复用已有二级导航下的路由级 Tab；
3. 作为已有页面内入口；
4. 新增二级导航；
5. 确有独立业务目标、稳定访问需求和完整闭环时，才新增一级导航。

业务模型归属与产品入口可以不同。某项能力可以在业务上归入已有大类，但为了突出独立产品价值单独设置入口；此时必须记录拆分原因，不代表建立新的永久业务关系。

## 6. 变更影响检查

本节不维护 AES 模块之间的固定上下游关系，只根据本次需求和当前证据识别可能受影响的菜单、Tab、页面入口和首页内容。

### 6.1 触发条件

- 新增或删除业务对象、任务类型、状态或操作；
- 新增跨页面跳转或对象关联；
- 修改列表字段、统计口径、待办或快捷入口；
- 修改菜单、Tab、路由或页面入口；
- 修改被多个模块复用的组件、状态或数据；
- 一个页面开始展示或操作另一个模块的数据。

### 6.2 代码与资料检查

优先检查当前项目中的：

- 路由和菜单配置；
- 页面跳转代码、链接配置和统一导航方法；
- 跨模块组件引用；
- 共享状态、Composable、事件或共享查询结果；
- 首页和全局工作台的统计、待办和快捷入口数据来源；
- 本次变更涉及的业务对象、状态、类型和操作的引用位置；
- 项目业务知识库中的入口、流程和跳转说明。

### 6.3 影响判断

检查以下问题：

- 当前菜单或路由级 Tab 是否需要新增、调整或迁移；
- 其他页面是否存在进入当前功能的入口；
- 当前页面是否存在跳转到其他模块的入口；
- 首页或全局工作台是否使用本次变更涉及的统计、状态或待办；
- 共享组件、状态或数据变化是否影响其他页面；
- 原有页面、路由或菜单是否可能失效。

仅因两个模块看起来相关，不能直接判定为受影响。代码或资料发现的引用先标记为需要核验，是否修改由后续设计和用户确认决定。

### 6.4 影响状态

| 状态 | 含义 |
| --- | --- |
| `confirmed` | 用户、代码或产品资料已明确存在影响 |
| `needs_verification` | 发现可能引用或共同数据，需要进一步确认 |
| `no_known_impact` | 当前证据未发现导航或全局入口影响 |

## 7. 输出契约

```yaml
aes_navigation_result:
  navigation_status: confirmed | inferred | needs_confirmation
  evidence:
    - source: user_input | project_code | product_material | aes_reference
      detail: ""
      version_or_time: ""
  navigation_path:
    level_1: ""
    level_2: ""
    level_3_tab: ""
  entry_type: level_1 | level_2 | level_3_tab | page_entry | modal_or_drawer
  navigation_format:
    global_shell: left-navigation
    left_navigation_levels: level_1_and_level_2
    level_3_presentation: header_tab
    l_shaped_navigation: false
  recommendation:
    recommended_level_1: ""
    reason: ""
    basis: business_domain | value_highlight | existing_structure | user_specified
  impact_check:
    status: confirmed | needs_verification | no_known_impact
    affected_surfaces: []
    related_modules_to_verify: []
    evidence: []
  navigation_gaps: []
  blocking_questions: []
```

`recommendation` 是未指定入口时的候选，不等同于最终菜单；`impact_check` 是本次需求的影响检查结果，不作为永久业务关系保存。影响面必须附带代码、用户输入或产品资料证据。

## 8. 与 Common Design 的关系

- AES 当前菜单分类、命名、层级和页头 Tab 归属，以当前 AES 证据为准；
- Common Design 只补充独立菜单、菜单 Tab 和页面内入口的通用判断；
- Common Design 的产品导航文档不能替代 AES 当前菜单现状；
- Common Design 的 `l-shaped` 导航不适用于 AES；
- Common Design 的页面模板在导航路径确定后再按需读取；
- Common Design 不得新增或改写 AES 的一级分类、二级菜单名称和三级 Tab 归属。

## 9. 进入主题层的准出条件

- 已确认或明确标记导航路径状态；
- 已确认入口类型；
- 已确认左侧导航只承载一级、二级导航；
- 已确认三级内容使用路由级Tab，且不使用 L 型导航；
- 已记录当前导航证据；
- 已执行必要的首页和跨模块影响检查；
- 未确认的菜单名称、路径或新增层级已进入待确认问题。

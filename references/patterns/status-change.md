# AES 业务对象状态切换模式

## 定位与命中

本 Reference 统一 AES 中既有业务对象的状态切换样式和交互，例如策略、规则和任务计划的「启用 / 禁用」，以及病毒的「待处置 / 已处置」。适用于列表、详情、抽屉及其他可直接修改对象状态的位置。

出现用户可执行的离散状态变更时自动执行本 Reference，不要求用户额外说明使用状态下拉或二次确认。若同一状态同时出现在列表和详情等多个入口，所有入口必须共同执行。

不适用于：

- 执行中、成功、失败等由系统推进的过程或结果状态。
- 只读状态，或状态集合、可达关系和操作后果尚未明确的场景。
- 新增或编辑表单中的配置项开关；此类控件执行对应表单和业务 Reference。

状态集合、可达关系、权限和业务后果由需求、主题 Reference、接口或真实页面提供，本 Reference 不自行补充。

## 统一样式

- 使用「状态图标 + 状态文案 + 下拉箭头」，完整区域为同一点击目标；不得使用 Switch 或另设普通按钮替代。
- 启禁用优先复用 `StatusDropDownMenu`；已有专用状态组件时复用真实组件，例如病毒状态使用 `DisposeCell`。不得在业务页面自行拼装样式。
- 菜单只展示当前对象允许到达的状态，当前状态保持选中；再次选择当前状态不触发确认、请求或反馈。
- 展开时箭头旋转，关闭后恢复；状态变化不得引起入口或周边布局跳动。
- 不可操作时保留当前图标和文案，入口不可展开，并在已有承载或 Tooltip 中说明具体原因。
- 同一状态在列表、详情和抽屉中使用相同的值、文案、图标、目标状态和确认链路。

### 状态样式确定规则

1. AES 已有相同业务状态和语义时，直接复用现有组件、图标和颜色。
2. 没有现成样式时，仍按「状态图标 + 状态文案 + 下拉箭头」设计；颜色映射到 AES 已有的成功、警示、危险、停用或中性等视觉语义，不自行新增颜色体系。
3. 图标须先查询项目当前版本的 IDUX 图标库里的面性图标（Filled），再按状态含义选择最合适的图标；不得自绘 SVG、使用其他图标库或仅凭颜色区分状态。
4. 新状态需同时明确文案、业务语义、允许到达的状态和切换后果。状态数量不限制为两个，菜单展示当前对象所有可达状态。
5. 新映射一经确定，在列表、详情、抽屉、单条和批量入口中统一复用。

现有复用基线：

| 状态 | 复用基线 |
| --- | --- |
| 启用 / 禁用 | `StatusDropDownMenu` 现有状态样式 |
| 待处置 / 已处置 | 病毒列表和详情的 `DisposeCell` 状态样式 |

## 单条切换

```text
选择不同的目标状态
→ 调用 tiered-confirmation.md
├─ 取消 → 保持当前状态
└─ 完成确认 → 提交状态变更
   ├─ 成功 → 提示结果并重新获取业务真值
   └─ 失败 → 保持当前状态并展示原因
```

- 用户选择不同状态后必须自动调用 `tiered-confirmation.md`，不得因需求未提及二次确认而省略。
- 确认方式和容器完全使用该 Reference 的返回结果；确认内容应明确对象、目标状态、实际操作数量及已知后果。
- 用户完成确认前不得提前显示目标状态。提交期间只锁定本次操作入口，防止重复提交。
- 成功后重新获取业务真值。列表保留搜索、筛选、排序和页码；详情或抽屉保持当前容器、页签和阅读位置。

## 批量切换

批量切换使用列表工具栏。固定动作使用「启用」「禁用」等按钮；同类动作需要归组时使用业务动作下拉，例如「标记 → 标记已处置 / 标记待处置」。不同目标状态分别计算可执行性。

执行某个目标状态前，先完成状态特有的对象分类：

```text
当前状态 != 目标状态 → 可执行候选
当前状态 == 目标状态 → 排除，原因：已是目标状态，无需重复操作
```

再将已选对象、可执行候选、排除对象和原因传给 `action-eligibility.md`，由其决定入口状态、是否允许部分执行和范围反馈：

- 未勾选或全部不可执行：当前按钮或菜单项禁用，不进入确认，不发送请求。
- 部分可执行：仅在该 Reference 允许部分执行时继续，并在确认前说明实际操作数量、跳过数量和原因。
- 全部可执行：作用于全部已选对象。

二次确认的对象数量和请求对象必须使用最终可执行范围：

```text
confirmation.object_count = executable_count = request_count
```

例如勾选 10 条数据，其中 6 条已处置，执行「标记为已处置」时，仅 4 条进入确认和请求，另外 6 条在确认前说明因状态相同被跳过。执行结果及刷新执行 `../templates/list.md`，不得把确认前排除的对象伪装为执行成功。

## 验收条件

- 所有可操作的业务对象状态使用统一状态下拉，没有使用 Switch；列表与详情等入口保持一致。
- 新状态优先复用 AES 视觉语义；无现成样式时使用 AES 语义色和项目当前版本的 IDUX 图标，没有自定义图标或仅用颜色表达状态。
- 单条切换选择当前状态不产生确认、请求或反馈；选择不同状态直接进入分级确认。
- 取消确认、请求失败或刷新失败时不会提前显示目标状态，提交期间不能重复触发。
- 不可执行入口不能展开或触发操作，并能看到与当前对象和目标状态匹配的原因。
- 批量操作先调用 `action-eligibility.md`，并按每个目标状态分别计算资格；状态相同的对象不会重复提交。
- 批量确认数量、实际请求数量和最终可执行数量一致，跳过范围在提交前可见。
- 成功刷新后，列表与详情等入口展示同一业务真值，并保留各自页面上下文。

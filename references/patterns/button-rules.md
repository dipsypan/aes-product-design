# AES 按钮命名规则

## 使用边界

本 Reference 只定义按钮、下拉操作组和新页签跳转入口的命名结构。

- 不负责按钮位置、样式、权限、确认方式和执行结果。
- 按钮承载动作时，优先遵循本文件。
- 按钮承载确认、筛选或表单提交时，继续遵循对应模板或细则。

## 命名原则

### 1. 动作按钮以“动作 + 对象”为主

按钮如果承载明确业务动作，名称应直接表达动作和对象，避免只写泛化词。

例如：

```text
隔离资产
结束进程
启动客户端
禁用客户端
升级客户端
```

### 2. 同一对象上的配对动作可以短写

如果按钮与主动作构成同一对象上的配对操作，且界面上下文已经明确对象，可以省略重复名词，保留用户一眼能理解的短名。

例如：

```text
隔离资产
解除隔离
```

这里的 `解除隔离` 等同于 `解除资产隔离`，不是独立语义。

### 3. 分组入口只命名操作族，不堆叠子动作

按钮组、下拉菜单、更多操作入口，只命名它收纳的操作族或业务范围，不把所有子动作写进入口名。

当名称表达的是分组，而不是立即执行的动作时，优先使用“对象 + 动作”的结构，让用户先识别管理对象，再理解这组操作的能力范围。

例如：

```text
资产隔离
批量操作
客户端管理
处置
```

- `资产隔离` 用于收纳资产隔离相关动作，例如 `隔离资产`、`解除隔离`。
- `批量操作` 用于收纳多项批量动作。
- `客户端管理`、`处置` 这类名称用于描述动作集合或业务范围。
- 入口名不写成 `批量隔离资产`、`批量结束进程` 这类叠词。

### 4. 菜单项保持具体动作名

下拉菜单中的每一项，仍然使用具体动作名。

例如：

```text
批量操作
  - 隔离资产
  - 结束进程

客户端管理
  - 启动客户端
  - 禁用客户端
  - 升级客户端
```

### 5. 批量只表示操作范围，不写入按钮名称

“批量”只说明这次动作作用于多选对象，不进入单个按钮名称。

即使是批量删除，按钮也只写 `删除`，批量含义由已选对象承载。

例如：

```text
删除
启用
禁用
```

不推荐：

```text
批量删除
批量启用
批量禁用
```

只有收纳多个动作的入口可以命名为 `批量操作`。

### 6. 新页签跳转入口在右侧追加 `↗`

如果按钮点击后打开新页签，或明确跳转到独立模块 / 外部页面，名称右侧追加 `↗`，不再额外加“打开”“前往”“进入”等冗余前缀。

注意：这里的 `↗` 仅作跳转图标示意，实际实现可使用同义跳转图标，不是固定字符。

例如：

```text
查询情报↗
文件隔离区↗
任务详情↗
```

### 7. 同一下拉菜单内，跳转项沉底展示

同一下拉菜单内，跳转类项置于动作类项之后，统一沉底展示。

若菜单同时包含动作和跳转，跳转项与动作项之间可用分割线区隔，但排序原则是不变的。

## 反例

以下写法不推荐：

```text
批量删除
执行隔离
更多操作
打开查询情报
```

原因：

- `批量删除` 把范围写进了按钮名。
- `执行隔离` 动词重复，语义不够直接。
- `更多操作` 只描述容器，不描述业务含义。
- `打开查询情报` 对新页签入口增加了冗余动词。

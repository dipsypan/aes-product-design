# AES dropdown 下拉菜单设计规范

> `Coverage: extend`
> **归属：AES Product Design。** 本 Reference 用于 AES dropdown 的触发形态、选项分组、排序和横线展示，不作为 Common Design 的通用组件规范。

## Component 身份

- `componentId: dropdown`
- `encapsulation: false`
- 实现基准：dropdown + `IxMenu`

## 基本使用

dropdown 用于承载一组操作选项，适用于操作入口较多、需要收纳展示的场景；用户选择菜单项后执行对应操作。

- 浮层内容使用 `IxMenu`；
- `IxMenu` 设置 `selectable="false"`，dropdown 不展示选中态；
- 通过 `visible.sync` 控制菜单显隐。

## 触发形态

dropdown 根据所在区域使用以下触发形态：

- **文字形态**：蓝色文字 + 下拉图标。用于表格操作列，少部分情况下也可用于详情的局部内容区。
- **按钮形态**：按钮文字 + 尾部内嵌向下箭头。用于非表格操作列场景，例如表格批量操作区、详情顶部操作区。

选择形态时还需检查同一区域并列放置的其他触发器，并与其保持一致。按钮形态不使用分裂按钮或独立的尾部操作按钮。

## 下拉菜单面板中的分组横线

分组横线仅用于 dropdown 展开后的下拉菜单面板，用于分隔面板内不同业务分组，不作用于触发按钮或其他页面区域。

下拉菜单面板不展示分组标题，仅通过选项顺序和横线表达业务分组。

仅同时满足以下条件时展示横线：

- 面板中的选项数 `>= 3`；
- 至少有一个分组包含 2 个或以上选项。

如果所有选项均为单独分组，即使选项较多，也不展示横线。横线只出现在不同分组之间，不出现在面板首尾或同一分组内部。

## 实体操作排序

实体操作按以下顺序排列：

1. 处置：删除、禁用等；
2. 恢复处置：恢复、解除禁用等；
3. 添加规则：添加白名单规则、添加黑名单规则；
4. 调查：文件名、文件路径、Hash、情报调查等。

“添加规则”的优先级高于“调查”。当前状态或权限不适用的操作直接隐藏，不保留空分组。

## 约束

- 不因选项多而自动增加横线；
- 不为展示横线虚构分组；
- 权限、状态、确认方式和操作结果由上游业务规则决定。

# AES 资产适用检测 Feature

> **归属：AES Product Design。** 本 Reference 是 AES（深信服下一代端点安全）产线专属 Feature，不作为 Common Design 的通用能力规范。
> `Coverage: extend`
> 本文明确规定的 AES 能力规则优先；未覆盖事项由 `prd-design-code` 按 Coverage 调用 Common Design 补充。

## 1. 定位与调用条件

本 Feature 用于选择一个资产，并检测该资产适用的策略或规则，同时标识实际生效项。

仅在 Theme 返回 `asset_applicability_check.enabled=true` 时调用：

- 策略检测使用「资产适用策略检测」，`entity_type: strategy`。
- 规则检测使用「资产适用规则检测」，`entity_type: rule`。
- 对象固定全局生效、不存在资产范围差异时不调用。

Theme 负责判断能力是否启用以及检测的业务实体；本 Feature 不重新判断业务范围。

## Feature 身份与封装

- `featureId: asset-applicability-check`
- `encapsulation: true`
- `componentId: CheckPolicyModal`，读取 [`../06-components/check-policy-modal.md`](../06-components/check-policy-modal.md)。
- 封装负责检测弹窗和通用阶段交互；业务页面负责实体、结果字段和权限。

## 2. 入口

- 入口位于列表左侧操作区，在对象管理操作之后、导入/导出之前。
- 入口不依赖列表勾选，显示时始终可点击。
- 同一列表只保留一个检测入口，不在行操作或其他区域重复生成。
- 点击入口后打开 AES 现有资产适用检测弹窗，不自行设计另一套检测流程。

## 3. 检测流程

```text
打开检测
   ↓
检索资产
   ↓
从检索结果选择一个资产并开始检测
   ↓
展示该资产适用的策略或规则
   ↓
标识实际生效项
```

### 3.1 检索资产

- 默认检测对象为单个资产，支持按资产名称、IP 等已有检索能力查找。
- 初始不预选资产，也不默认展示任意资产的检测结果。
- 检索结果按列表展示，每行提供「开始检测」入口。
- 一次只检测一个资产，不使用表格批量勾选。
- 资产组检测只有在 Theme、接口和现有产品能力均明确支持时才开放，不根据概念相似性自动增加。

### 3.2 展示检测结果

- 用户点击「开始检测」后，将所选资产作为当前检测对象，并展示适用结果。
- 结果必须包含识别业务实体所需的信息；策略基线可包含优先级、状态、名称、描述和分配来源，规则场景按 Theme 提供的字段替换。
- 对接口返回的实际生效项显示明确标识，不根据列表顺序自行推断。
- 结果存在多个适用项时全部展示，不只展示最终生效项。
- 实体名称只有在存在真实详情或编辑入口时才允许点击跳转。

### 3.3 更换检测对象

- 当前检测对象在检索区清晰回显。
- 移除当前对象后返回资产检索状态，并清空上一次检测结果。
- 重新检索或选择其他资产时，不保留上一资产的结果。

## 5. 状态与异常

- 检索中和检测中分别展示加载状态，避免用户重复触发。
- 未找到资产时展示资产检索无结果，不误写成“无适用策略/规则”。
- 已选择资产但没有适用项时，展示当前资产无适用结果。
- 资产检索失败和检测失败分别说明失败环节，并提供重试入口。
- 关闭弹窗后结束当前检测；再次打开时回到初始检索状态。
- 检测只用于查看适用关系，不在结果列表中直接修改启用状态、优先级或分配范围。

## 7. 准出条件

- Theme 已明确 `enabled`、`entity_type` 和入口名称。
- 固定全局生效时没有生成检测入口。
- 入口不依赖列表勾选，并且没有重复生成。
- 用户能够完成检索资产、开始检测、查看全部适用项和识别实际生效项。
- 更换检测对象后不存在上一资产的残留结果。
- 已区分资产无结果、无适用项、检索失败和检测失败。
- 规则场景只替换业务实体与结果字段，没有重新设计检测流程。

## 实现绑定

- `componentId: CheckPolicyModal`，读取 [`../06-components/check-policy-modal.md`](../06-components/check-policy-modal.md)。
- 来源：`AES__APP_LIB/PolicyCommon`
- 列表入口直接复用检测弹窗封装，不重新实现资产检索、检测状态或“开始检测”流程。
- 编码阶段必须核验目标分支的实际导出名、路径、Props、API 配置和结果字段。

## 业务补充

- 业务页面负责注入资产列表、策略/规则关联结果、详情跳转配置和权限条件。
- `entity_type`、结果字段、实际生效项标识及成功/失败状态仍由本 Feature 决定。
- 封装不足或业务结果超出 `CheckPolicyModal` 能力时，仅补充缺口，不改变本 Feature 的检测流程。

# AES 表格导入规则

> `Coverage: override`

## 使用边界

本 Reference 用于产品内列表的数据批量导入。

- 先由列表模板确定业务对象和字段，再调用本 Reference。
- 本 Reference 只定义导入入口、流程、状态、结果和异常反馈，不定义具体业务字段、权限模型或后端接口。
- 资产身份信息导入属于独立业务流程，以 MAC 地址匹配资产并更新身份字段，不适用本 Reference。

## Feature 身份与封装

- `featureId: import`
- `encapsulation: true`
- `componentId: BatchImportModal`，读取 [`../06-components/batch-import-modal.md`](../06-components/batch-import-modal.md)，并按需配合其内部导入进度、结果和失败弹窗封装。
- 来源：`AES__APP_LIB/Impex`
- 封装负责弹窗承载和通用阶段切换；本 Feature 仍负责业务字段、冲突策略、状态、结果、异常和列表更新。
- 编码阶段必须核验目标分支的实际导出名、Props、Events 和任务状态接口。
- 封装不足或业务行为超出封装范围时，按本 Feature 契约补充实现，不得假设已有完整导入能力。



布局要求：

- 导入配置弹窗负责准备和提交，不展示后台任务进度。
- 导入进度弹窗负责反馈任务，不允许返回修改文件或冲突策略。
- 导入结果弹窗负责解释最终结果，不继续显示处理中进度。
- 进度弹窗应比结果弹窗更紧凑；结果弹窗需要为数量摘要和异常表格预留空间。
- 含失败或冲突的结果必须采用“摘要区 + 异常信息列表 + 底部确认操作”的纵向结构。
- 异常报告下载按钮位于摘要区右侧或同一信息层级，不放在底部操作区；底部只保留“我知道了”或等价的完成操作。
- 异常信息列表固定使用五列：行号、类型、异常字段、导入内容、异常描述。
- 任务切换时关闭上一阶段的主弹窗，再打开下一阶段，避免多个主弹窗叠加。
- 没有任务中心、通知或其他恢复入口时，不允许用户无反馈关闭、刷新或离开进行中的任务。

阶段流转：

```text
导入前 --提交成功--> 导入中 --完成/失败--> 导入后
  ^                    |
  |                    +--任务创建失败--> 导入后（失败结果）
  +--上传失败/文件过期-+
```

## 入口与配置

- 将导入作为列表工具栏的全局操作，不要求先选择表格行。
- 按“下载模板 → 上传文件 → 设置冲突规则 → 提交导入”的顺序组织流程。
- 上传前校验文件格式、空文件和文件大小；未上传有效文件时禁用“导入”按钮。
- 当不同冲突策略会产生不同业务结果时，对重复数据提供明确的冲突策略；若无特殊说明，使用“跳过”和“替换”，默认选择“跳过”。
- 若重复数据采用不同策略的最终结果相同，则不展示策略选项，改为顶部提示重复数据直接跳过。
- 业务字段校验由服务端完成，前端必须展示服务端返回的行号、字段、内容和原因。

## 进行中状态

- 区分文件上传和导入任务两个阶段，分别反馈上传进度和导入进度。
- 提交成功后关闭配置弹窗，进入独立的导入进度状态，展示文件名和进度。
- 防止重复提交和重复查询。
- 文件过期时清理旧文件状态，并引导用户重新上传。
- 没有恢复入口时，不允许进行中的任务被无反馈关闭。

## 结果与异常

导入结果分为三种状态，使用两类布局：完全成功和文件级校验失败使用紧凑反馈布局；已进入逐行处理且存在失败或冲突时，使用异常明细布局。

### 结果判定与固定文案

1. 完全成功
   - 条件：已完成逐行处理，失败数为 0 且冲突数为 0。
   - 使用紧凑反馈布局，展示成功图标、标题和数量摘要，只保留关闭入口。
   - 标题固定为“导入完毕”。
   - 数量文案固定为“`{{新增数}} 条新增`”。
2. 文件级校验失败
   - 条件：文件表头、格式或必填字段不符合要求，未进入逐行数据处理，因此没有行级结果和异常列表。
   - 使用紧凑反馈布局，展示失败图标、标题和失败原因，只保留关闭入口。
   - 标题固定为“导入失败”。
   - 原因文案固定为“`失败原因：{{失败原因}}`”，例如“失败原因：文件表头缺少必填字段：资产组名称”。
3. 存在失败或冲突
   - 条件：已完成逐行处理，且失败数大于 0 或冲突数大于 0。
   - 使用“摘要区 + 异常信息列表 + 底部确认操作”的异常明细布局。部分成功、全部失败、部分冲突和全部冲突均使用此布局，不得改用紧凑失败提示或另建结果样式。
   - 标题固定为“导入完毕”。
   - 导入时选择“跳过”，摘要固定为“`共处理 {{处理行数}} 行数据，{{新增数}} 条新增、{{失败数}} 条失败、{{冲突数}} 条因与已有信息冲突已跳过`”。
   - 导入时选择“替换”，摘要固定为“`共处理 {{处理行数}} 行数据，{{新增数}} 条新增、{{失败数}} 条失败、{{冲突数}} 条因与已有信息冲突已替换`”。
   - 未提供冲突策略选项时，按产品实际采用的固定策略显示“已跳过”或“已替换”，不得同时展示两种处理结果。

### 数量口径

- “处理行数”指导入文件的数据行数；“新增数”指平台实际新增的业务记录数。一行数据可能新增多条记录，因此新增数可以大于处理行数。
- 各项数量使用接口返回值，不得自行推算，也不要求满足“处理行数 = 新增数 + 失败数 + 冲突数”。


### 异常明细

- 异常明细至少包含行号、异常类型、异常字段、导入内容和异常描述。
- 服务端返回有效报告文件时，提供“下载异常报告”；没有文件时不显示无效下载入口。
- 导入完成后刷新列表，清空旧选择，并按页面约定重置分页。

## 状态清理

- 流程结束后清理文件、冲突策略、进度、结果和临时选择状态。
- 关闭结果弹窗后不得残留上一次任务的文件名、数量或异常数据。
- 页面卸载或流程切换时停止查询，避免后台定时器继续更新已失效页面。

## 验收重点

- 验证导入入口在无数据、无选择和有筛选等状态下的可用性。
- 验证导入前配置、导入中进度、导入后结果按顺序切换，且不会同时叠加多个主弹窗。
- 验证文件校验、冲突策略和进度展示。
- 验证完全成功、文件级校验失败，以及含失败或冲突的统一异常结果，包括全部失败和全部冲突。
- 验证结果文案符合固定模板：完全成功显示“导入完毕”和“`{{新增数}} 条新增`”；文件级校验失败显示“导入失败”和“`失败原因：{{失败原因}}`”；存在失败或冲突时显示“导入完毕”和完整的处理结果摘要。
- 验证异常结果摘要中的“已跳过”或“已替换”与导入时选择或产品固定采用的冲突策略一致，不得混用；处理行数、新增数、失败数和冲突数均使用接口返回的实际值。
- 验证处理行数与新增数使用各自的统计口径，包括一行数据创建多条业务记录的情况。
- 验证文件过期、任务失败、异常报告、列表刷新和状态清理。

# AES 跨模块快速新增备注默认值 Feature

> `Coverage: extend`
> **归属：AES Product Design。** 本 Reference 是 AES（深信服下一代端点安全）产线专属 Feature，不作为 Common Design 的通用默认值规范。本文仅约束任务和规则的 `备注` 字段。

## 1. 适用范围

仅用于从其他业务模块基于当前对象快速新增任务或规则时，初始化表单的 `备注` 字段。

以下场景不适用：

- 任务模块或规则模块自身的常规新增；
- 编辑已有任务或规则；
- 任务重新下发。

## Feature 身份与封装

- `featureId: contextual-remark-default`
- `encapsulation: false`
- 当前没有对应的 AES 前端业务封装，按本 Feature 规则实现。

## 2. 来源信息

```yaml
source_context:
  entry_type: quick-create | module-create | re-dispatch | edit
  source_module_name: ""
  source_object_name: ""
```

- `source_module_name` 使用来源模块的实际页面展示名称。
- `source_object_name` 使用来源页面展示的具体对象名称。
- 不得根据对象 ID、类型、规则内容、时间或其他字段自行生成对象名称。

## 3. 备注回填规则

仅当 `entry_type=quick-create` 且来源模块名称、来源对象名称均存在时，回填：

```text
通过{模块名称}【{具体对象名称}】添加
```

来源模块名称或对象名称缺失时，`备注`保持为空。默认备注只在新增表单初始化时回填一次，不因其他字段变化、重新校验或局部刷新重复覆盖。

## 4. 用户修改规则

- `备注`为可编辑的选填字段。
- 用户编辑、追加、删除或清空默认备注后，均视为手动修改。
- 手动修改后不得再次自动回填或覆盖，包括用户清空默认备注的情况。
- 提交失败重新展示表单时，保留用户最后输入的备注。
- 最终保存值以用户提交值为准，来源信息不作为任务或规则字段保存。

## 5. 任务重新下发

任务重新下发不是快速新增。重新下发基于原任务生成新任务时，新任务备注直接沿用原任务已保存的备注，不重新生成来源备注。

## 6. 验收标准

- 任务和规则自身常规新增时，备注为空。
- 其他模块快速新增且来源对象名称存在时，按实际模块名和对象展示名回填。
- 来源对象名称缺失时，备注为空，不能生成替代名称。
- 用户修改或清空默认备注后，任何后续状态变化都不覆盖备注。
- 任务重新下发时，新任务备注与原任务已保存备注一致。
